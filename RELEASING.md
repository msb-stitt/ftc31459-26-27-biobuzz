# Lesson work and releases

The guide's answer pages, its cheat sheet and the review are generated by applying the
`solutions/` that `book/keep.toml`'s `[answers]` names, and the pages say which. A lesson is worked
on a `lessons-X` branch, with its answers on a `solutions-X` branch beside it. Lessons merge into
solutions; solutions never merge into lessons.

A finished round merges into `dev`, and every push to `dev` publishes the books in `dev/` on the
site. A release fast-forwards `main` to a commit of `dev` and tags it there. A push to `main`
publishes nothing.

`keep.toml` is changed with `tools/pin.py`, not by hand. While a lesson is worked on it names the
solutions branch, so the tools read its tip, and its `[media]` follows the corbels-lfs-lessons
branch of the same name. On `dev` and `main` it names a solutions tag and a media commit, so the
pages stay those of one commit of each.

## A round of lesson work

- Start it, on the lessons branch, with `python tools/run.py pin --follow solutions-X` in `book/`.
  It names the branch in `keep.toml`, clears the media commit and regenerates the pages; commit
  what it writes. After a release, this is what moves the next round off the release's tag.
- Push `solutions-X` before a lessons branch that follows it. CI fetches what `keep.toml` names,
  and fails when it is not on `origin`.
- Work, merging lessons into solutions as often as needed. On every push CI checks the answer
  pages, the cheat sheet and the review against what `keep.toml` names.
- End it, as the last commit before the merge to `dev`, with `ninja pin` in `book/`. It tags the
  branch's tip `solutions-X.N` with the next number, or names the tag that already holds the same
  `solutions/`, and pins the media to the tip of its branch on corbels-lfs-lessons' `origin`, so
  push the media first. It regenerates the pages and commits nothing. Commit what it writes, push
  the tag, then push the commit.
- On a lessons branch, CI fails a pinned tag whose `solutions/` is no longer the branch's, since
  the patches changed after pinning; pin again. Merging lessons into solutions moves the branch's
  tip without changing `solutions/`, so it does not make a pin stale.
- Merge to `dev`. CI fails on `dev` and `main` when `keep.toml` names anything but a solutions tag
  and a media commit. Look at `dev/` on the site after the push.

## Building what a release publishes

```
book/.venv/bin/pip install -r book/requirements-publish.txt
cd book && PATH="$PWD/.venv/bin:$PATH" ninja publish-check
```

`ninja publish-check` builds both books with every figure in place, the review and both PDFs into
`book/build/publish/`, and publishes nothing. It runs `book/tools/build.py` on the last commit, so
commit first. It fails if a figure is still a pencilled box, a page shows an image that is not
there, or a page links a video the media pin does not have. Its PDFs link the top level's videos;
`release.yml` passes `--as` and `--version`, so a published PDF links its own version's. It is not
part of `ninja book`.

The figures come from
[corbels-lfs-lessons](https://github.com/msb-stitt/corbels-lfs-lessons), in Git LFS, at the commit
`book/keep.toml`'s `[media]` pins, or its branch while none is. `publish-check` reads a clone of it
beside this repository, or the one `--media DIR` names, and fails if that clone is at another
commit or its figures were not pulled from LFS:

```
git clone https://github.com/msb-stitt/corbels-lfs-lessons.git ../corbels-lfs-lessons
cd ../corbels-lfs-lessons && git lfs install --local && git checkout <the [media] commit, or its ref> && git lfs pull
```

## Making a release

- Take any new screenshots into corbels-lfs-lessons' `figures/` first, and run
  [`ninja publish-check`](#building-what-a-release-publishes), which fails on a figure still
  missing.
- Try it as a pre-release: tag a commit of `dev` `vX.Y.Z-rc.N` and push the tag. It gets its own
  folder on the site while it is newer than the newest release, and a GitHub pre-release. The run
  stops if the tag is not on `dev`, or if `keep.toml` names a solutions branch.
- Release it: fast-forward `main` to that commit, push `main`, then tag `main`'s head `vX.Y.Z` and
  push the tag. The run stops unless the tag is at `main`'s head and on `dev`.

  ```
  git switch main && git merge --ff-only <the commit> && git push origin main
  git tag -a vX.Y.Z -m "<what is new>" && git push origin vX.Y.Z
  ```

- [`release.yml`](.github/workflows/release.yml) makes `gh-pages` again as one commit with no
  history: the newest release at the top level, where the links in the code point, a newer
  pre-release in its own folder, `dev/`, and no older version. Each has its own `videos/`, from
  its media pin, which its pages link relatively; a page written `` {video}`l020` `` links it. The
  front page links every version's GitHub Release. The GitHub Release carries both PDFs, the
  videos, and the web pages with the videos as `ftc31459-vX.Y.Z-web.zip`, and the media commit is
  tagged in corbels-lfs-lessons with the same name. A tag's PDFs link the videos in its GitHub
  Release, and `dev`'s link `dev/videos/`. A video is pulled from LFS only when `gh-pages` serves
  no copy of it.
- Look at the published books after: a page of each guide and of each PDF.
- The next round starts with `pin --follow`, as above.
