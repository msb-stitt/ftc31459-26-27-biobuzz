L100: let AutoTune tune the robot¶

The robot measures itself. It finds which way each motor turns and where the pods sit. It finds how fast it can drive and how hard it can brake. Pedro Pathing’s AutoTune does the measuring. You paste what it finds into Constants.java.

Do this after L115, which mounts the Pinpoint this lesson tunes.

The steps¶

L100S010: open AutoTune¶

AutoTune is a web page the robot serves. It is not in the Driver Station’s list of OpModes. It starts its own OpMode, called Pedro Tuning, when a step needs the robot to move.

Send. Send the code to the robot, as in L050. Join the laptop to the robot’s Wi-Fi. In a browser, open http://192.168.43.1:10158.

Check. The page lists four tuners: Mecanum Tuner, Tests, Pinpoint Tuner and Foresight Tuner.

L100S020: find which way each motor turns¶

Put the robot on blocks, so its wheels spin freely.

Robot. Pick Mecanum Tuner. Type the four motor names as the Robot Configuration spells them: Front Left, Front Right, Back Left and Back Right. Each motor then spins on its own, at half power, beside a picture of which wheel it is. Say whether it spun, and whether it spun forward or reversed.

Change. At the end, AutoTune shows Java that starts public static MecanumConfig drivetrainConfig. Open Constants, in the pedro folder. Find the eight lines that set the names and directions. Put the eight AutoTune shows in their place. Keep manualBrakeMode and powerThreshold. AutoTune does not print them.

Check. The directions match what L050 found on blocks.

L100S030: measure the pods¶

The Pinpoint needs four more numbers: which way each pod counts, and how far each one sits from the middle of the robot. The x offset is how far sideways the forward pod is from the point the robot turns about, and left counts up. The y offset is how far forward the strafe pod is, and forward counts up. This robot’s are about 1.06 in and 3.36 in.

Put the robot on the floor.

Robot. Pick Pinpoint Tuner. Keep the name pinpoint and the pod type it offers. Then do the three pushes it asks for, stopping each one when you are done:

  • Push the robot forward.

  • Push the robot to the left.

  • Spin the robot half a turn on the spot, counterclockwise.

Change. Replace localizerConfig in Constants with the PinpointConfig AutoTune shows.

Check. In Tests, pick Localization Test and drive with the gamepad. Driving forward raises x, and strafing left raises y.

L100S040: let the robot find its speed and its brakes¶

This one drives itself. Clear the floor first.

Robot. Pick Foresight Tuner. Keep the distances and the speed it offers: 48 in, 30 in/s and 36 in. It drives forward and left as fast as it can, coasts to a stop, turns back and forth, spins, brakes, and steps 12 in to 24 in each way.

Change. Replace foresightConfig in Constants with the ForesightConfig AutoTune shows. Keep the five lines it does not print, from translationalConstraint to holdPointHeadingScaling.

Three of its numbers are kept twice in Constants, for the lessons’ own drivetrain. Copy each one up into its own line:

  • the number in c.coast.set(...) goes in powerPerInchPerSecond;

  • maxAchievableForwardVelocity goes in maxForwardInchesPerSecond;

  • maxAchievableStrafeVelocity goes in maxStrafeInchesPerSecond.

Check. Each of the three pairs holds the same number.

L100S050: watch it drive a line¶

Send. Send the code again, so the new Constants is on the robot.

Robot. In Tests, pick Line Test, with the distance at 48.

Check. The robot drives 48 in and stops on the line.
