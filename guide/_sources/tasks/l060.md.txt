**Check.** `mytry` holds `L060ShapingOpMode`, and the new file is open.

### L060S020: switch your copy on

**Change.** Delete the line `@Disabled`, under the comment that names this step.

**Check.** Under the step's comment, the next line reads
`// public: the robot only runs an OpMode that is public.`

### L060S030: write a deadband

A stick that has been let go does not always read 0. It can read a few hundredths, and a few
hundredths of power is enough to make a robot crawl across the floor on its own. A **deadband**
fixes that: any reading closer to the middle than the band counts as let go.

**Change.** Scroll to the bottom of the file and find the comment that names this step. Under it,
write a method of your own:

```{code-block} java
:emphasize-lines: 4-9

    // When on L060S030, see
    // https://msb-stitt.github.io/ftc31459-26-27-biobuzz/guide/tasks/l060.html#l060s030
    // for what to do here.
    double deadband(double value, double band) {
        if (Math.abs(value) < band) {
            return 0;
        }
        return value;
    }
```

A **method** is a named piece of code you can use again. This one takes two numbers, `value` and
`band`, and gives back one number. `return` is the number it gives back.

`Math.abs` takes the minus sign off: `Math.abs(-0.03)` is 0.03. `deadband` is given the speed, so a
stick pulled halfway back gives -0.5, and -0.5 is less than 0.05. But it is far from the middle, so
it has to be compared without its minus sign.

**Check.** The method has no red underline. Android Studio shows `deadband` in grey, with
*no usages* above it, because nothing uses it yet.

### L060S040: use the deadband

**Change.** In `loop()`, under the comment that names this step, make a power for each side:

```{code-block} java
:emphasize-lines: 4-8

        // When on L060S040, see
        // https://msb-stitt.github.io/ftc31459-26-27-biobuzz/guide/tasks/l060.html#l060s040
        // for what to do here.
        double band = 0.05;
        double leftPower = deadband(leftSpeed, band);
        Tracker.publish("power/left", leftPower);
        double rightPower = deadband(rightSpeed, band);
        Tracker.publish("power/right", rightPower);
```

Then change the four `setPower` lines below, so each one gets the power and not the speed:

```java
        hardware.frontLeft.setPower(leftPower);
        hardware.backLeft.setPower(leftPower);

        hardware.frontRight.setPower(rightPower);
        hardware.backRight.setPower(rightPower);
```

**Simulator.** In the Terminal, run:

```
./gradlew :TeamCode:simRun --args="mytry.L060ShapingOpMode --pad"
```

**AdvantageScope.** Connect to the simulator as in L020. Drag `left` from the `speed` folder and
`left` from the `power` folder into **Left Axis**.

**Check.** Let go of the sticks. `speed/left` may sit a little off 0, and `power/left` reads 0.
The wheels in `sim/wheels` all read 0.

### L060S050: write squaring

With the deadband in, a tenth of a push is still a tenth of the power. Near the middle that is more
robot than a driver wants. **Squaring** fixes it: half a push becomes a quarter of the power, and a
full push is still full power.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Find the comment that names this
step. Under it, write a second method:

```{code-block} java
:emphasize-lines: 4-6

    // When on L060S050, see
    // https://msb-stitt.github.io/ftc31459-26-27-biobuzz/guide/tasks/l060.html#l060s050
    // for what to do here.
    double squared(double value) {
        return value * Math.abs(value);
    }
```

`value * value` would lose the minus sign: -0.5 times -0.5 is 0.25, and backward would turn into
forward. `value * Math.abs(value)` keeps it: -0.5 times 0.5 is -0.25.

**Check.** The method has no red underline.

### L060S060: use squaring

**Change.** Go back to the two `deadband` lines from L060S040. Put `squared(` in front of
`deadband`, and one more `)` before the `;`:

```java
        double leftPower = squared(deadband(leftSpeed, band));
```

```java
        double rightPower = squared(deadband(rightSpeed, band));
```

`squared` works on what `deadband` gives back.

**Simulator.** Run the same command again, and connect AdvantageScope.

**Check.** Push the left stick halfway forward. `speed/left` reads 0.5, and `power/left` reads
0.25. Push it all the way, and both read 1. Pull it back, and the power goes below 0.

### L060S070: drive it on the robot

**Send.** Send the code to the robot, as in L050. On the Driver Station, pick `L060 Shaping` from
the `Lessons` group. Press INIT, then PLAY.

**Check.** Let go of both sticks, and the robot sits still. Push a stick about a third of the way,
and the robot creeps along under control. Push it all the way, and the robot goes full speed.

::::{only} mentor
**No gamepad.** `--args="mytry.L060ShapingOpMode --left_stick_y=-0.03 --right_stick_y=0.04"` holds
both sticks just off centre; the first picture was taken that way. `--left_stick_y=-0.5
--right_stick_y=0.5` holds them half forward and half back for the second.

**If it didn't**, and the robot still creeps on the floor, the band is smaller than what this
gamepad reads when it is let go. Raise it a little: 0.05 to 0.1 is the usual range. A band much
bigger than that throws away real driving.

**If it didn't**, and the robot goes forward but will not back up, a sign was lost. Check `squared`
uses `Math.abs`, and `deadband` too.

**What you just did.** Both methods sit between the speed and the wheels. Each one takes a number
and gives one back, and neither knows what a wheel is. `speed/left` is still what the stick asks
for, and `power/left` is what the wheels get, so AdvantageScope shows both side by side.
