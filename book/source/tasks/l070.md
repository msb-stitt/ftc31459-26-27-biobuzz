### L070S030: read the A button

A stick is a number. A button is only down or up, so Java keeps it as a **boolean**: `true` when
it is down, `false` when it is up.

`setPower` lines. Under it, type `boolean buttonA = gamepad1.a`. The list offers `a`, marked
`boolean`.

### L070S040: remember last loop's button

`buttonA` says whether A is down in this loop. To know the moment it changed, the code also needs
to know whether it was down in the loop before. A variable made inside `driveFromTheSticks()` is a
**local variable**. It is gone when the method ends, so this one goes outside it.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Scroll to the top of the class, and
find the comment that names this step. Under it,
type:

```{code-block} java
:emphasize-lines: 4

    // When on L070S040, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l070.html#l070s040
    // for what to do here.
    boolean previousButtonA;
```

A variable made here is a field, as `band` is in L065's `StickShaper`. It keeps its value from one
loop to the next. A `boolean` field starts out `false`.

**Check.**

- The line has no red underline.

### L070S050: say when the button changes

**Change.** Back in `driveFromTheSticks()`, find the comment that names this step. Under it, type:

```{code-block} java
:emphasize-lines: 4-11

        // When on L070S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l070.html#l070s050
        // for what to do here.
        if (buttonA != previousButtonA) {
            if (buttonA) {
                Tracker.publish("gamepad1/buttonAEvent", "A pressed");
            } else {
                Tracker.publish("gamepad1/buttonAEvent", "A released");
            }
        }
        previousButtonA = buttonA;
```

`!=` means "is not the same as". The first `if` is true only on the loop where the button changed.
The second one says which way it changed. `else` is what runs when the `if` is false. The last line
saves this loop's button for the next loop.

The text in quotes is a **String**. `Tracker` writes it down the same way it writes a number.

**Simulator.** Run the same command again, and connect AdvantageScope.

**AdvantageScope.** Drag `buttonAEvent` from the `gamepad1` folder into **Discrete Fields**. Until A
has been pressed once, `buttonAEvent` is crossed out, because nothing has been written to it yet.

Holding A down does not write `A pressed` again. `buttonAEvent` only changes on the loop the button
changed.

**Check.**

- Press A and hold it. `gamepad1/buttonA` turns into a green dot, and `buttonAEvent` reads `A
  pressed`.
- Let go. The dot turns red, and `buttonAEvent` reads `A released`.

### L070S060: read the sticks sideways

Each stick also moves left and right. Pushed right, it reads above 0.0. Pushed left, it reads below
0.0. Tank drive does not use these yet. Later lessons drive sideways with them.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Near the top of
`driveFromTheSticks()`, find the comment that names this step, under the lines that read the sticks
up and down. Under it, type:

```{code-block} java
:emphasize-lines: 4-7

        // When on L070S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l070.html#l070s060
        // for what to do here.
        double leftStickX = gamepad1.left_stick_x;
        Tracker.publish("gamepad1/leftStickX", leftStickX);
        double rightStickX = gamepad1.right_stick_x;
        Tracker.publish("gamepad1/rightStickX", rightStickX);
```

**Simulator.** Run the same command again, and connect AdvantageScope.

**Check.**

- Push the left stick to the right, and `gamepad1/leftStickX` goes above 0.0.
- Push the right stick to the left, and `gamepad1/rightStickX` goes below 0.0.
- The speeds in `drivetrain` stay at 0.0, and the robot does not move.

### L070S070: watch the buttons on the robot

**Robot.** Stop the simulator. Send the code, run `L070 Buttons` from the Driver Station, and watch

::::{only} mentor
**No gamepad.** `--args="mytry.L070ButtonsOpMode --a=true"` holds A down for the whole run, so
`buttonAEvent` reads `A pressed` and never changes; the picture at the top was taken that way. A
release needs a gamepad. `--left_stick_x=0.5 --right_stick_x=-0.25` holds the sticks sideways for
the last picture. The tests press and let go of A without a gamepad.

**If it didn't**, and `buttonAEvent` reads `A pressed` but never `A released`, the last line,
`previousButtonA = buttonA;`, is missing. The test fails with `letting go says so`.

**If it didn't**, and `buttonAEvent` reads `A pressed` when A is let go, the two `Tracker.publish`
lines are swapped.

**What you just did.** A boolean is either `true` or `false`. A field keeps a value between loops,
and comparing this loop with the last one finds the moment something changed. That is how a
button press can do one thing once, rather than once every loop it is held.
