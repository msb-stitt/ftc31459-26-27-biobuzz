# L120: work out where the robot is from the drive wheels

:::{admonition} fig-l120-shadow-still
:class: pencil
AdvantageScope's 2D Field and list with the `Localizer` folder open: `pinPoint/y_in` at 83.078 while
the robot drives forward, and `driveWheelEncoders` still at x 72, y 10.5 and heading 90, where it
started.
:::

Your own localizer runs beside the robot's own, and both are published so they can be graphed
against each other. Yours counts how far the four drive wheels roll. The robot's own counts the
Pinpoint's two pods. Neither is the truth. A tape measure is.

::::{only} mentor
**Before you start.**

- L110 is done, so the follower holds a real drivetrain, and L115 is done, so the Pinpoint is on the
  robot.
- AdvantageScope is installed on the same laptop, and a gamepad is plugged into the laptop.
- The robot on blocks, as in L050, the Driver Station, a tape measure, and about 3 m of clear floor
  for the last step.

Step L120S060 is written from the code and the old `l8` page. It has not been performed on a robot
yet.

The simulator turns each wheel's encoder by how far the wheel rolls, at `Constants.ticksPerInch`,
and turns the IMU with the robot. It has no slip, so a finished localizer follows the Pinpoint
there more closely than it will on the robot. The tests check the arithmetic step by step.
::::

### L120S040: add up how far the wheels rolled

`update` runs once a loop. Each time, it can only see how far each wheel has rolled in total, so it
remembers last loop's numbers and takes them away.

The first loop has nothing to take away from, so it only remembers.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Open `L120EncoderLocalizer`. In
`update`, find the comment that names this step. Under it, type:

```{code-block} java
:emphasize-lines: 4-19

        // When on L120S040, see
        // https://msb-stitt.github.io/ftc31459-26-27-biobuzz/guide/tasks/l120.html#l120s040
        // for what to do here.
        if (lastWheels == null) {
            lastWheels = wheels.clone();
            lastRawHeading = rawHeading;
            return;
        }

        double frontLeft = wheels[0] - lastWheels[0];
        double frontRight = wheels[1] - lastWheels[1];
        double backLeft = wheels[2] - lastWheels[2];
        double backRight = wheels[3] - lastWheels[3];

        double forward = (frontLeft + frontRight + backLeft + backRight) / 4;
        double strafe = (-frontLeft + frontRight + backLeft - backRight) / 4;

        x += forward;
        y += strafe;
```

Android Studio types the `}` for you when you press Enter after the `{`. Type the rest below it.

`null` means "nothing yet". `.clone()` makes a copy, so next loop's numbers do not change it.
`return` leaves `update` early, until next loop.

The two long lines are L090's table read backwards. There, three numbers made four wheel powers.
Here, four wheel moves make `forward` and `strafe` again, in inches.

**Check.**

- In the Terminal, run this. It prints `8 tests completed, 2 failed`, then `BUILD FAILED` and more
  red lines. That is what failing tests look like here, and two are meant to fail now.

  ```
  ./gradlew :TeamCode:testDebugUnitTest --tests '*L120EncoderLocalizerTest*'
  ```

The two that fail are
`appliesTheHeadingSoSidewaysIsRelativeToTheRobot` and
`setPoseMovesTheEstimateWithoutMovingTheRobot`. Both are about which way the robot faces. That is
the next step.

### L120S050: turn the step to face the way the robot faces

:::{admonition} fig-odometry-step
:class: pencil
One loop of dead reckoning: the four wheel travels since the last loop, the forward and left arrows
those add up to, the same pair turned to point along the robot's heading, and the old estimate with
that pair added on the end.
:::

`forward` is forward for the robot, not for the field. The robot starts facing along the field's y,
so its forward is the field's y. L120S040 added it to x.

**Change.** Delete the two lines `x += forward;` and `y += strafe;`. Find the comment that names
this step. Under it, type:

```{code-block} java
:emphasize-lines: 4-6

        // When on L120S050, see
        // https://msb-stitt.github.io/ftc31459-26-27-biobuzz/guide/tasks/l120.html#l120s050
        // for what to do here.
        double heading = rawHeading + headingOffset;
        x += forward * Math.cos(heading) - strafe * Math.sin(heading);
        y += forward * Math.sin(heading) + strafe * Math.cos(heading);
```

`Math.cos` and `Math.sin` share the step out between x and y. Facing along x, `cos` is 1 and `sin`
is 0, so forward all goes on x. Facing along y, `cos` is 0 and `sin` is 1, so forward all goes on y.
In between, each gets a part.

`heading` counts in **radians**, not degrees. One whole turn is about 6.28 radians. `Math.cos` and
`Math.sin` use radians.

**Check.**

- Run the same test command again. It ends with `BUILD SUCCESSFUL`.

### L120S060: drive it, then measure it

**Robot.** Stop the simulator. Send the code, run `L120 Compare Localizers` from the Driver
Station, and watch it in AdvantageScope.

**Check.**

- Drive about 80 in straight ahead and stop. Both `y_in` numbers moved, and they do not quite agree.
- Measure how far the robot really went with the tape measure.

Then put the robot on the blocks and push the left stick forward. The wheels spin, and the robot
does not go anywhere. `driveWheelEncoders` walks off across the field. `pinPoint` stays put,
because its pods are off the floor too.

**If it didn't**, and `driveWheelEncoders` is missing from the `Localizer` folder in L120S030, the
two lines are not in `shadowLocalizers()`.
`LessonsTest.l120_theEncoderLocalizerRunsAlongsideAndIsLogged` fails with
`the shadow localizer is logged:` and the list of names that were published.

**If it didn't**, and `countsStrafingLeft` fails with `left is +y when facing +x`, a sign in the
`strafe` line is wrong. With the sign in front of `frontRight` flipped, it reads
`expected:<12.0> but was:<6.0>`, and three other tests fail with it.

**If it didn't**, and all 8 tests fail with
`Cannot load from double array because "this.lastWheels" is null`, the first-loop `if` is missing.

**What you just did.** That is **dead reckoning**: believe the wheels, and add up every step. It
has no other source, so a wheel that spins without carrying the robot moves the estimate. The test
`aWheelThatSlipsIsSimplyBelieved` shows it on a laptop: one wheel rolling 24 in on its own moves
the estimate 6 in. The Pinpoint's pods only measure and never push, so they slip less. That is the
case for having them.

The heading here is the one at the end of each step. While driving and turning at once, the middle
of the step would be closer, and the old `l8` used it. Taking the end needs no subtraction of two
headings, so a turn through the back of the circle needs no care.

The localizer reports a speed of zero. Only `x_in`, `y_in` and `heading_deg` are published for a
shadow, so nothing reads its speed.
