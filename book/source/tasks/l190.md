# 190 lesson: ask the wheels for a speed

:::{admonition} fig-l190-wheel-numbers
:class: pencil
Stand-in for `fig-l190-wheel-numbers`, a screenshot.
:::

Full stick means 40 inches per second, not `setPower(1.0)`. The drivetrain measures how fast each
wheel turns and makes up the difference, on a fresh battery or a flat one, on the flat or up a
slope.

::::{only} mentor
**Before you start.**

- L180 is done.
- AdvantageScope is installed on the same laptop, and a gamepad is plugged into the laptop.
- The robot, the Driver Station, a gamepad, about 3 m of clear floor, and something gentle to drive
  up, like a folded mat, for the last step.
::::

### L190S050: turn the sticks into speeds

:::{admonition} fig-l190-asks-standing-still
:class: pencil
Stand-in for `fig-l190-asks-standing-still`, a screenshot.
:::

`MAX_IPS` is 40.0, in inches per second. `MAX_TURN_RADPS` is pi radians per second, half a turn
each second. Both are near the top of the class.

**Change.** In `driveFromTheSticks()`, find the comment that names this step. Under it are three
lines that end in `= 0.0;`, each with its `publish` line. Above each one, type the two lines that
make the stick's speed, and change its `0.0` as below. Then, under the last `publish` line, type the
last lines:

```{code-block} java
:emphasize-lines: 4-6,8-10,12-14,17-20

        // When on L190S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l190.html#l190s050
        // for what to do here.
        double forwardXSpeed = -leftStickY;
        forwardXSpeed = stickShaper.shaped(forwardXSpeed);
        double forwardX_ips = forwardXSpeed * MAX_IPS;
        Tracker.publish("drivetrain/forwardX_ips", forwardX_ips);
        double strafeYSpeed = -leftStickX;
        strafeYSpeed = stickShaper.shaped(strafeYSpeed);
        double strafeY_ips = strafeYSpeed * MAX_IPS;
        Tracker.publish("drivetrain/strafeY_ips", strafeY_ips);
        double turnCcwSpeed = -rightStickX;
        turnCcwSpeed = stickShaper.shaped(turnCcwSpeed);
        double turn_radps = turnCcwSpeed * MAX_TURN_RADPS;
        Tracker.publish("drivetrain/turn_radps", turn_radps);

        double[] wheel_ips = WheelTargets.forMecanum(forwardX_ips, strafeY_ips, turn_radps,
                Constants.turnRadiusInches);
        drivetrain.setCommandedWheelSpeeds(wheel_ips[FL], wheel_ips[FR], wheel_ips[BL],
                wheel_ips[BR]);
```

The minus signs are the ones from L030. A stick pushed up reads less than 0.0. The starter sets
`stickShaper` to `LINEAR` in `init()`, so it applies the deadband and does not square the speed.
Each speed is a fraction of full speed, and times `MAX_IPS` it becomes inches per second. The end of
a name says its unit: `_ips` is inches per second, and `_radps` is radians per second.

`WheelTargets.forMecanum` works out how fast each wheel has to turn for the robot to move like
that. It hands back an array, front left first, then front right, back left and back right, which
`FL`, `FR`, `BL` and `BR` pick out, as in L113. `turnRadiusInches` is how far each wheel sits from
the middle of the robot.

`WheelTargets` and `Constants` turn red. Hold the mouse over each one until a box offers **Import
class**, and click it. The box for `Constants` names
`org.firstinspires.ftc.teamcode.pedro.Constants`.

**Simulator.** In the Terminal, run:

```
./gradlew :TeamCode:simRun --args="mytry.L190VelocityDriveOpMode --pad"
```

**AdvantageScope.** Connect to the simulator as in L020, click **2D Field**, and open the
`drivetrain` folder. Then open `Localizer` and `pinPoint`.

**Check.**

- Push the left stick halfway forward and hold it.
- `forwardX_ips` reads about 20, half of 40.
- The robot does not move, and `y_in` stays at 10.5.

The OpMode asks for a speed, but `setCommandedWheelSpeeds` in your drivetrain is still empty.

### L190S060: turn inches per second into a fraction of full speed

:::{admonition} fig-speed-loop
:class: pencil
Stand-in for `fig-speed-loop`, made by `book/tools/draw.py`.
:::

Open `L190SpeedDriveTrain`. It `extends CorbelsMecanum`, so it has everything L180's drivetrain had.
`setCommandedWheelSpeeds` puts the four speeds into the array `wanted_ips`. Each wheel gets its
fraction of full speed from two parts added together.

- **Feedforward** is a guess, made before anything is measured. `Constants.powerPerInchPerSecond` is
  the fraction of full speed one inch per second needs, so the guess gets most of the way there at
  once.
- **Feedback** is the correction. `measuredSpeeds.all()` reads how fast each wheel really turns.
  The difference between wanted and measured, times `VELOCITY_KP`, is added on.

The guess is always a little off, and the correction only grows once the wheel is off its speed.
Together they get there and stay there.

A `for` loop runs the lines inside its braces once for each wheel. `i` starts at 0 and goes up by
1 each time, while it is less than 4. So `wanted_ips[i]` is `wanted_ips[FL]` the first time
around, then `FR`, `BL` and `BR`.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. In `setCommandedWheelSpeeds`, find
the comment that names this step. Under it, type:

```{code-block} java
:emphasize-lines: 4-12

        // When on L190S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l190.html#l190s060
        // for what to do here.
        double[] measured_ips = measuredSpeeds.all();
        double[] wheelSpeeds = new double[4];
        for (int i = 0; i < 4; i++) {
            double feedforward = Constants.powerPerInchPerSecond * wanted_ips[i];
            double feedback = VELOCITY_KP * (wanted_ips[i] - measured_ips[i]);
            wheelSpeeds[i] = clampToFullSpeed(feedforward + feedback);
        }
        setCommandedWheels(wheelSpeeds[FL], wheelSpeeds[FR], wheelSpeeds[BL], wheelSpeeds[BR]);
        publishWheelSpeeds(wanted_ips, measured_ips);
```

Android Studio types the `}` of the `for` loop for you, when you press Enter after the `{`.

`clampToFullSpeed` keeps each speed between -1.0 and +1.0. `setCommandedWheels` sends the four to
the wheels, as in L110. `publishWheelSpeeds` puts each wheel's numbers in the `wheel` folder.

`Constants` turns red. Import it as in L190S050.

**Simulator.** Run the same command again.

**AdvantageScope.** Connect, and open `wheel`, then `frontLeft`.

**Check.**

- Push the left stick a fifth of the way forward, less than before, so the robot stays on the
  field longer.
- `forwardX_ips` and `target_ips` read about 8.
- The robot drives up the field.
- As it starts, `speed` reads more than the guess, about 0.134: the correction adds to it for a
  wheel not yet turning.

`actual_ips` climbs to about 8 in under half a second and settles a little above 8, so `error_ips`
settles a little below 0.0. `speed` drops to about 0.13 and stays there. The guess was a little too
much for the simulated robot, and the correction takes off what it needs.

### L190S070: drive it up something

**Robot.** Stop the simulator. Send the code, run `L190 Velocity Drive` from the Driver Station,
and watch it in AdvantageScope.

**Check.**

- Drive on the flat first.
- Then drive straight up the mat, with the stick held in the same place. The robot slows a little at
  the foot of the slope and then picks back up.
- In AdvantageScope, `actual_ips` dips below `target_ips`, then climbs back, and `speed` rises to do

::::{only} mentor
**No gamepad.** `--args="mytry.L190VelocityDriveOpMode --left_stick_y=-0.5"` holds the stick for
L190S050, and `--left_stick_y=-0.2` in its place holds it for L190S060.

With `--left_stick_y=-0.2`, the first loop's `speed` reads 0.198. That is the guess, 0.134, plus
the correction for a wheel not yet turning.

**If it didn't**, and every `LessonsTest.l190_` test fails with this, no wheel's speed was published
under `wheel/`:

```
NullPointerException: Cannot invoke "java.lang.Double.doubleValue()" because the return value of "java.util.Map.get(Object)" is null
```

L190S060 is not typed yet, or `publishWheelSpeeds` is missing. The test asks the log for a number
nobody wrote. The same message comes when the `drivetrain.setCommandedWheelSpeeds` line in
L190S050 is missing.

**If it didn't**, and a test fails with one of these, the line named is the one to look at. Each was
planted and run.

- `full stick asks for a speed, in inches per second expected:<40.0> but was:<0.0>`: the three
  speeds are still `0.0`.
- `expected:<40.0> but was:<1.0>`: `* MAX_IPS` is missing. A full stick is 1.0, and 1 inch per
  second is very slow.
- `expected:<40.0> but was:<-40.0>`: the minus sign in front of `leftStickY` is missing.
  `l190_whenTheWheelsAreUpToSpeedOnlyTheFeedforwardRemains` fails with it, saying
  `expected:<0.0> but was:<-80.0>`.
- `turning counter-clockwise drives the left side backwards`, on its own: the minus sign in front of
  `rightStickX` is missing.
- `expected:<0.9878391425450086> but was:<0.6678391425450086>`: the feedback is not added. The
  difference is `0.008 * 40.0`.
- `expected:<0.9878391425450086> but was:<0.32>`: the feedforward is not added. A wheel already at
  speed then gets 0.0.
- `expected:<0.9878391425450086> but was:<0.34783914254500864>`: the error is the wrong way around,
  `measured_ips[i] - wanted_ips[i]`.
- `measured speed matches the command expected:<40.0> but was:<0.0>`: `measured_ips` is not read
  from `measuredSpeeds.all()`.

Two mistakes pass every test. Both were run in the simulator with `--left_stick_y=-0.2`, and in
both the `wheel` numbers were right while the robot stood still at x 72 in, y 10.5 in.

- `setCommandedWheels` is missing, so the speeds are worked out and logged but never sent.
- `initAfter();` was left as it was, so the follower holds a stand-in and never sends them on,
  as in L110.

A number in the log is what the code decided, not what the robot did.

**If it didn't**, and on the robot it is slower than `target_ips` everywhere,
`powerPerInchPerSecond` is off for this robot. L117 measures it. If turning is the wrong speed
while driving straight is right, `turnRadiusInches` is 8 in, and this robot may not be. L195
measures it.

**What you just did.** A fraction of full speed is an instruction, and inches per second is a
result. Every lesson before this one sent instructions. This one states the result it wants,
measures, and corrects.
