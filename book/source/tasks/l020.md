The `lessons` folder holds the starters: the file each lesson begins from. You copy one into your
own folder, `mytry`, and change the copy.

- A box called **Copy Class** opens with **Destination package** already ending in `mytry`. Click
  **OK**.

### L020S020: switch your copy on

**Change.** Find the line `@Disabled`, just under the comment that names this step. Click on it and
delete the whole line: ⌘Delete on a Mac, Ctrl+Y on Windows and Ubuntu. The first time on Windows,
Android Studio asks whether Ctrl+Y should Redo or Delete Line: click **Delete Line**.

`@Disabled` hides an OpMode from the robot's list. The starter in `lessons` keeps it, so the robot
only ever lists your copy.

**Check.**

- Under the step's comment, the next lines read
  `// 'public' so the robot can run this OpMode. 'public' allows access from any code.` and
  `public class L020SticksOpMode`.

### L020S030: read the left stick

The file is an **OpMode**: one program the robot can run. Pressing INIT runs its `init()` once.
Pressing PLAY runs its `start()` once, and `start()` hands `readTheSticks()` to the **scheduler**.
From then until STOP, the scheduler runs `readTheSticks()` over and over, many times a second. The
simulator presses all three for you.

**Change.**

{.steps}
- Scroll down to `readTheSticks()` and find the comment that names this step.

- Click at the end of its last line and press Enter. Type this much:

  ```java
  double leftStickY = gamepad1.
  ```

- A list opens with everything a gamepad has. Type `left_st` and the list shrinks to the left
  stick.

- `left_stick_y` is already highlighted. Press Tab. If it isn't, move the highlight to it with the
  arrow keys first.

- Type `;` to end the line.

:::{admonition} fig-l020-complete
:class: pencil
Stand-in for `fig-l020-complete`, a screenshot.
:::

```{code-block} java
:caption: mytry/L020SticksOpMode.java
:emphasize-lines: 4

        // When on L020S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l020.html#l020s030
        // for what to do here.
        double leftStickY = gamepad1.left_stick_y;
```

`double` is Java's word for a number with a decimal point, like 0.5 or -1.0. `leftStickY` is a name
you chose for one. The list said `float`, which is a smaller kind of decimal number. A `double`
holds any `float`.

Now hold the pointer still over `left_stick_y`. A box opens and says what it is: *left analog stick
vertical axis*. You can do this with any name you are not sure about.

- The line has no red underline.

### L020S040: write the left stick down

**Change.** Under the comment that names this step, type `Track`. The list shows more than one
`Tracker`. Pick the one from `org.firstinspires.ftc.teamcode.base` and press Tab. Then finish the
line:

```{code-block} java
:caption: mytry/L020SticksOpMode.java
:emphasize-lines: 4

        // When on L020S040, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l020.html#l020s040
        // for what to do here.
        Tracker.publish("gamepad1/leftStickY", leftStickY);
```

:::{admonition} fig-l020-tracker
:class: pencil
Stand-in for `fig-l020-tracker`, a screenshot.
:::

`Tracker.publish` takes a name and a value. It sends both to AdvantageScope while the code runs, and
writes them in the flight log. Android Studio added an `import` line for `Tracker` near the top of
the file.

**Check.**

- `Tracker` is not red, and there is an `import org.firstinspires.ftc.teamcode.base.Tracker;` line
  near the top.

The simulator is a robot that exists only in the laptop. It runs your OpMode just as the real robot
would.

**Simulator.** Click the **Terminal** button near the bottom of the left edge. Type this and press
Enter:

```
./gradlew :TeamCode:simRun --args="mytry.L020SticksOpMode --pad"
```

**Check.**

- It lists any connected gamepads.
- Then it prints `Flight log:` and a folder, then `mytry.L020SticksOpMode running.`, and stays
  running.
- The folder is the project's top folder, the one that holds `README.md`.

If more than one gamepad is plugged in, hold Start and press A on yours, so it becomes `gamepad1`.

AdvantageScope draws the numbers your code publishes, as they change.

**AdvantageScope.**

{.steps}
- Open AdvantageScope. It is an app of its own, not a part of Android Studio.

- Open **File > Connect to Simulator > NetworkTables 4**. The item marked **Default** works the
  same. Then click **Line Graph**.

- Type `leftStickY` in the search box at the top left, and click `NT:/gamepad1/leftStickY`.

- Drag `leftStickY` from the `gamepad1` folder down into **Left Axis**.

Before you push the stick, guess. When you push the left stick all the way away from you, will the
line go to 1.0 or to -1.0? Now push it and see!

**Check.**

- The line moves when you push.
- All the way forward it reads -1.0, and all the way back it reads 1.0.

Forward is -1.0 on gamepads. That is how most gamepads are made, not a mistake in your code.

**What's happening.** [E021](e021.md) shows what your two lines do inside the computer.

::::{only} mentor
**What you just did.** `readTheSticks` runs over and over, from PLAY until STOP, and each pass is
one look at the gamepad. The code read both sticks into `double`s and wrote each one down under a
name. AdvantageScope showed the values live, and the flight log kept them to look at after the run.

**The scheduler.** `start()` makes `readTheSticks` into a command that never finishes, with
`Commands.infinite`, and schedules it. The scheduler runs every scheduled command once a loop,
inside `loopAfter()`. Every lesson's code runs this way; L170 is the first to schedule a second
command, on a button.

**The stick's axes.** A stick reads from -1.0 to +1.0 on each axis. +x is pushed to the driver's
right, and +y is pulled back toward the driver, so forward on the stick is -y. From L030 on, a stick
asks the robot for a velocity: the farther the push, the faster.

:::{admonition} fig-stick-to-robot
:class: pencil
Stand-in for `fig-stick-to-robot`, made by `book/tools/draw.py`.
:::

**Turning a stick into a velocity changes axes.** Forward is `-left_stick_y`, a slide to the left
is `-left_stick_x`, and a counter-clockwise turn is `-right_stick_x`. The stick's axes are a mirror
image of the robot's, so no turn of the gamepad lines them up, and each needs its minus sign. L030
makes the first, `-leftStickY`; L080 adds the turn and L090 the slide. L140 adds a second change,
from the field's axes to the robot's.

**Where next.** [L030](l030.md) turns each stick into a speed, where forward is positive.
