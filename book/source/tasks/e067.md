# 067 what's happening: drawing a class and its calls

When the computer runs your program, it reads one line of code at a time. It moves words and
numbers around in its memory. It is like moving sticky notes around on your desk.

In [L065](l065.md) you wrote a class, `StickShaper`, and an OpMode that uses it. Programmers draw
classes in pictures called **UML**, the Unified Modeling Language. Here are two of them: a class
diagram, of what each class has, and a sequence diagram, of who calls whom.

## the class diagram

A **{ref}`class diagram <uml-class>`** is a box for each class: its name, then its fields, then its
methods. Here is a small class, `A`, drawn as a box, and its code:

:::{admonition} fig-uml-class
:class: pencil
Stand-in for `fig-uml-class`, made by `book/tools/draw.py`.
:::

```{code-block} java
:class: example
public class A {
    double size;

    public A(double startSize) {
        size = startSize;
    }

    public double grow(double by) {
        size = size + by;
        return size;
    }

    double half() {
        return size / 2;
    }
}
```

- `double size` is a field: its type, then its name.
- `+` in front of a name means **public**: any code can use it. `A`'s constructor and `grow` are
  `public`.
- No mark means any class in the same folder can use it. `half` has no mark.
- `: double` after a method is what it gives back.

An arrow with a diamond means **{ref}`has-a <uml-has-a>`**: the class at the diamond holds the other
one. A field makes it. Here `A` has-a `B`:

:::{admonition} fig-uml-has-a
:class: pencil
Stand-in for `fig-uml-has-a`, made by `book/tools/draw.py`.
:::

```{code-block} java
:class: example
public class A {
    B b;
}
```

{ref}`«enumeration» <uml-enum>` marks an `enum`. Its box lists the values it can be. Here `A` holds
(has-a) a `Mode`, which is `ON` or `OFF`:

:::{admonition} fig-uml-enum
:class: pencil
Stand-in for `fig-uml-enum`, made by `book/tools/draw.py`.
:::

```{code-block} java
:class: example
public class A {
    public enum Mode { ON, OFF }

    Mode mode = Mode.ON;
}
```

## the sequence diagram

A **{ref}`sequence diagram <uml-call>`** shows calls in time order, from the top down. Each object
has a box and a dashed line down from it. The box says the object's name, then its class:
`stickShaper:` is the field's name, and `StickShaper` is its class. A solid arrow is a call, and a
dashed arrow is what the call gives back.

Here an object `a` calls `grow(2)` on an object `b` of class `B`, and 5 comes back:

:::{admonition} fig-uml-call
:class: pencil
Stand-in for `fig-uml-call`, made by `book/tools/draw.py`.
:::

```{code-block} java
:class: example
        double total = b.grow(2);
```

An arrow marked {ref}`new <uml-new>` makes the object at its end:

:::{admonition} fig-uml-new
:class: pencil
Stand-in for `fig-uml-new`, made by `book/tools/draw.py`.
:::

```{code-block} java
:class: example
        B b = new B(3);
```

These are the lines you wrote, with the left stick halfway forward and the right stick halfway
back:

```{code-block} java
:caption: mytry/l065/L065ShaperOpMode.java
    StickShaper stickShaper = new StickShaper(0.05);
```

- The first arrow is `new`. It makes the object, and the constructor keeps 0.05 as its band. This
  happens once, when the OpMode is made.

```{code-block} java
:caption: mytry/l065/L065ShaperOpMode.java
        double leftShapedSpeed = stickShaper.shaped(leftSpeed);
        double rightShapedSpeed = stickShaper.shaped(rightSpeed);
```

- `shaped(0.5)` hands the object the left speed. Its dashed arrow brings back 0.25: past the band,
  and squared.
- `shaped(-0.5)` hands it the right speed, and -0.25 comes back. Each time `loop()` runs, these
  two calls happen again.

In L065S080 you added `setShape(CUBED)` in `init()`. That is one more arrow, after `new` and before
the first `shaped`, and then `shaped(0.5)` gives back 0.125. No arrow from `driveFromTheSticks()`
changes.

The OpMode's arrows go only to `+` methods. It never calls `deadband` or `signedSquared`, and it
never reads `band` or `shape`. That is what makes the shape easy to change.
