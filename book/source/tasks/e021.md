# 021 what's happening: assignments

When the computer runs your program, it reads one line of code at a time. It moves words and
numbers around in its memory. It is like moving sticky notes around on your desk.

Here is what the two lines you wrote in [L020](l020.md) do. Each one is a **statement**: it tells
the computer to do one thing.

```java
double leftStickY = gamepad1.left_stick_y;
```

:::{admonition} fig-l020-sticky
:class: pencil
`double leftStickY = gamepad1.left_stick_y;` as sticky notes: the label `gamepad1` with an arrow to
a blue `Gamepad` note, the label `left_stick_y` on it with an arrow to a yellow `float` note holding
-0.7, and an orange arrow copying -0.7 onto the yellow `double` note that the label `leftStickY`
points to.
:::

- It makes a **variable**, `leftStickY`. A variable is a name, drawn as a white label, with an
  arrow to a sticky note. The note says what kind of value it holds: a `double`.
- `gamepad1` is a variable too. Its arrow points to the gamepad's big blue note. On that note is
  the **field** `left_stick_y`, a name kept on another note. Its arrow points to a small note that
  holds a `float`.
- The FTC platform does a lot of work for us. It runs `loop()` over and over. Before each pass, it
  writes the stick's newest position on that `float` note.
- The `=` copies that number onto `leftStickY`'s note. `=` is an action: put this value here.

```java
Tracker.publish("stick/leftY", leftStickY);
```

- `Tracker` has a **method**, `publish`: a piece of code with a name. This line runs it, the way
  the platform runs your `loop()`.
- The line hands it two things: a name for the value, in quotes, and `leftStickY`.
- `publish` sends the number on `leftStickY`'s note to AdvantageScope, and writes it in the flight
  log.
