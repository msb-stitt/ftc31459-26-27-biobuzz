# 132 lesson: compare your localizers with the Pinpoint's

Your localizers from L113 and L120 run beside the robot's own. Yours from L113 reads the drive
wheels. Yours from L120 reads the Pinpoint's pods once a loop. The robot's own reads the answer
the Pinpoint worked out on its own chip. All three are published so they can be graphed against
each other. Each loop, your code works out how far each of yours is from the robot's own, and how
fast your localizer from L120 says the robot goes. None of them is the truth. A tape measure is.

::::{only} mentor
**Before you start.**

- L113 and L120 are done, so `mytry` holds `L113EncoderLocalizer` and `L120PinpointLocalizer`,
  and L117 is done, so the Pinpoint is on the robot and tuned.
- AdvantageScope is installed on the same laptop, and a gamepad is plugged into the laptop.
- The robot on blocks, as in L050, the Driver Station, a tape measure, and about 3 m of clear floor
  for the last step.

### L132S040: see how often the loop runs

Your localizers work out where the robot is once each time `loop()` runs. The Pinpoint's chip
works it out on its own, about 1500 times a second. Between two of your loops, the robot moves a
little, and your localizer takes that move as one step.

**AdvantageScope.** Leave the simulator running. Open the `loop` folder and graph `period_ms`. It
is how long the last loop took. It is measured as the OpMode runs.

**Check.**

- `period_ms` is a few milliseconds or more, and it is not the same from one loop to the next.

The Pinpoint's chip takes about 0.7 ms a step. Write down what `period_ms` reads in the simulator,
to compare with the robot in the next step.

### L132S050: work out how far off each localizer is

The robot's own localizer is the one to compare against. Each loop, take each of your localizers'
x, y and heading, and subtract the robot's own. What is left is the **error**.

**Change.** In `start()`, find the comment that names this step. Under it, type:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-5

        // When on L132S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
        // for what to do here.
        Command compareWithPedrosEveryLoop = Commands.infinite(this::compareWithPedros);
        Scheduler.schedule(compareWithPedrosEveryLoop);
```

The scheduler runs `compareWithPedros()` before the localizers update. So it compares where each
one said the robot was last loop, all at the same moment.

**Change.** Find the comment for this step just above `shadowLocalizers()`. Under it, type a new
method:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-12

    // When on L132S050, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
    // for what to do here.
    /** How far one of your localizers is from the robot's own, in x, y and heading. */
    void publishError(String name, Pose yours, Pose pedros) {
        double xError_in = yours.x() - pedros.x();
        double yError_in = yours.y() - pedros.y();
        double headingError_rad = Angle.normalizeSigned(yours.heading() - pedros.heading());
        Tracker.publish("Error/" + name + "/x_in", xError_in);
        Tracker.publish("Error/" + name + "/y_in", yError_in);
        Tracker.publish("Error/" + name + "/heading_deg", Math.toDegrees(headingError_rad));
    }
```

A heading of 359° and one of 1° are only 2° apart. `Angle.normalizeSigned` turns a difference into
one between -180° and 180°, so the error is 2°, not 358°.

**Change.** In `compareWithPedros()`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-6

        // When on L132S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
        // for what to do here.
        Pose pedros = follower.pose();
        publishError("driveWheelEncoders", driveWheelEncoders.pose(), pedros);
        publishError("pinpointPods", pinpointPods.pose(), pedros);
```

`Pose` and `Angle` turn red. Click each one and press Option+Enter, as in L113.

**Simulator.** Run the simulator as in L132S030, and open the `Error` folder in AdvantageScope.

**Check.**

- Drive forward and turn. Each error stays within about half an inch, and the headings agree.
- Slide sideways. `driveWheelEncoders`' error grows in x or y, whichever way the robot slides.
  `pinpointPods`' error stays within a few tenths of an inch.

Your localizer from L113 thinks each wheel pushes at 45°. The wheels in the simulator push more
forward than that, as L113 showed, so it says the robot slid farther than it did.

### L132S060: put the speeds side by side

Your localizer from L120 says how fast the robot goes, from L120S070. So does the robot's own.

**Change.** In `compareWithPedros()`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-11

        // When on L132S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s060
        // for what to do here.
        Twist podsSpeed = pinpointPods.twist();
        Twist pedrosSpeed = follower.localizer.twist();
        Tracker.publish("Speed/pinpointPods/forward_ips", podsSpeed.vx);
        Tracker.publish("Speed/pinPoint/forward_ips", pedrosSpeed.vx);
        Tracker.publish("Speed/pinpointPods/strafe_ips", podsSpeed.vy);
        Tracker.publish("Speed/pinPoint/strafe_ips", pedrosSpeed.vy);
        Tracker.publish("Speed/pinpointPods/turn_degps", Math.toDegrees(podsSpeed.omega));
        Tracker.publish("Speed/pinPoint/turn_degps", Math.toDegrees(pedrosSpeed.omega));
```

`Twist` turns red. Click it and press Option+Enter.

**Simulator.** Run the simulator again, and open the `Speed` folder in AdvantageScope.

**Check.**

- Graph `pinpointPods/forward_ips` with `pinPoint/forward_ips`, and drive forward. Once the speed
  is steady, the two lines are within about 0.3 in/s.
- Do the same for `strafe_ips` while sliding, and `turn_degps` while turning.

### L132S070: drive it, then measure it

**Robot.** Stop the simulator. Send the code, run `L132 Compare Localizers` from the Driver
Station, and watch it in AdvantageScope.

**Check.**

- Drive about 80 in straight ahead and stop. The three `y_in` numbers moved, and they do not quite
  agree.
- Measure how far the robot really went with the tape measure.
- Read `loop/period_ms` on the robot, and compare it with what you wrote down in L132S040.
- Read the `Error` folder. On the robot, the error from the Pinpoint's own answer is real.

Then put the robot on the blocks and push the left stick forward. The wheels spin, and the robot
does not go anywhere. `driveWheelEncoders` walks off across the field. `pinpointPods` and
`pinPoint` stay put, because the pods are off the floor too.

**No gamepad.** `--args="mytry.L132CompareLocalizersOpMode --left_stick_y=-0.5"` drives forward.

**If it didn't**, and `driveWheelEncoders` or `pinpointPods` is missing from the `Localizer` folder
in L132S030, its three lines are not in `shadowLocalizers()`.
`LessonsTest.l132_yourLocalizersAreLogged` fails with `the shadow localizer is logged:` for

**If it didn't**, and `LessonsTest.l132_theErrorAndSpeedAreLogged` fails, each of these was planted
and run:

- `the wheels' error is logged:`: the lines of L132S050 are not typed, or the scheduler line is
  missing from `start()`.
- `yours less the robot's own, in y expected:<45.0> but was:<-45.0>`: the subtraction is the wrong
  way round, `pedros.y() - yours.y()`.

**What you just did.** Your localizer from L113 believes the drive wheels, and a wheel that spins
without carrying the robot moves its estimate. The Pinpoint's pods only measure and never push, so
they slip less. That is the case for having them. Your localizer from L120 and the Pinpoint's read
the same pods. They differ in how often they do the math: once a loop, or about 1500 times a
second.
