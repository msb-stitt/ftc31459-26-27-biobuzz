# L010: getting started

:::{admonition} fig-l010-built
:class: pencil
Android Studio with the project open and the Build window reading *BUILD SUCCESSFUL* and *63
actionable tasks: 63 executed*.
:::

Put the robot's code on the laptop and build it. After this, every lesson starts in Android Studio
with the project open.

::::{only} mentor
**Before you start.**

- A laptop running Windows, macOS or Ubuntu, signed in to an account that may install programs.
- The internet.
- No robot and no gamepad are needed.

Nothing else has to be installed first. Android Studio fetches Java 17 for the project by itself,
and git is installed in L010S040 when Android Studio asks for it.
::::

## The steps

### L010S010: install Android Studio

The robot's code is written in Android Studio. The team uses one version of it, **Quail 4**, so
everyone sees the same screens. It is not the newest, so it comes from the page of older versions.

**Download.**

{.steps}
- Open <https://developer.android.com/studio/archive> and click **I agree** under the terms.

- Click **Android Studio Quail 4 | 2026.1.4 Patch 1** to open it.

- Click the file for your laptop: `android-studio-quail4-patch1-windows.exe` for Windows,
  `android-studio-quail4-patch1-mac_arm.dmg` for a Mac with an Apple chip, or
  `android-studio-quail4-patch1-linux.tar.gz` for Ubuntu. It is about 1.5 GB.

:::{admonition} fig-l010-archive
:class: pencil
The archive page with *Android Studio Quail 4 | 2026.1.4 Patch 1* open, listing its installers and
zip files.
:::

**Windows.** Open the downloaded file. Click **Yes** when Windows asks to let it change your
device. In Android Studio Setup, click **Next** on each page, then **Install**, **Next** and
**Finish**.

:::{admonition} fig-l010-windows-setup
:class: pencil
Android Studio Setup's *Choose Components* page with *Android Studio* and *Android Virtual Device*
ticked.
:::

**macOS.** Open the file. Drag Android Studio onto the Applications folder, and start it from
there. If macOS says it came from the web, click **Open**.

:::{admonition} fig-l010-macos-applications
:class: pencil
The opened disk image with Android Studio beside the Applications folder.
:::

**Ubuntu.** Open Terminal and type these two lines, then your password when `sudo` asks:

```
sudo apt install libx11-6:amd64 libxext6:amd64 libxrender1:amd64 libxtst6:amd64 libxi6:amd64 libfreetype6:amd64 libfontconfig1:amd64 libxrandr2:amd64 libxcursor1:amd64 zlib1g:amd64
sudo tar -xzf ~/Downloads/android-studio-quail4-patch1-linux.tar.gz -C /opt
```

Then start Android Studio with `/opt/android-studio/bin/studio`. Leave that Terminal open while
you work.

:::{admonition} fig-l010-ubuntu-apt
:class: pencil
Terminal on Ubuntu with the `sudo apt install` line, the list of packages it installs, and
*Continue? [Y/n]*.
:::

**Check.**

- Android Studio starts and asks to *Help improve Android Studio*. Click **Don't send**.

::::{only} mentor
**If it didn't**, on Ubuntu, and Android Studio closes a few seconds after it starts with *Bus
error (core dumped)* in Terminal, turn off its Gemini plugin and start it again:

```
mkdir -p ~/.config/Google/AndroidStudio2026.1.4
echo com.google.tools.ij.aiplugin >> ~/.config/Google/AndroidStudio2026.1.4/disabled_plugins.txt
```

`bin/studio.sh` stops with *No JRE found*; start `bin/studio` instead.
::::

### L010S020: let Android Studio fetch what it needs

The first time it starts, Android Studio's setup wizard downloads the Android tools the code is
built with.

**Setup.**

{.steps}
- Click **Next** on *Welcome*.

- Pick **Standard** and click **Next**.

- Click **Next** on *Verify Settings*.

- Click each licence on the left, pick **Accept**, and click **Next**. On Ubuntu a page about KVM
  and the emulator comes next; click **Next**.

- Wait while it downloads, then click **Finish**.

:::{admonition} fig-l010-wizard-standard
:class: pencil
The setup wizard's *Install Type* page with *Standard* picked.
:::

**Check.**

- The last page of the wizard reads *Android SDK is up to date*. On Windows a red line under it,
  *SDK emulator directory is missing*, is fine.

- *Welcome to Android Studio* opens, with **New Project**, **Open** and **Clone Repository**.

If a note says *Rabbit 1 available*, leave it. The team stays on Quail 4.

### L010S030: install AdvantageScope

AdvantageScope draws what the robot is doing: where it is on the field, and graphs of its numbers.

**Download.** Open <https://github.com/Mechanical-Advantage/AdvantageScope/releases/tag/v26.0.2>.
Under **Assets**, click the file for your laptop:

- Windows: `advantagescope-win-x64-v26.0.2.exe`
- a Mac with an Apple chip: `advantagescope-mac-arm64-v26.0.2.dmg`
- Ubuntu: `advantagescope-linux-x64-v26.0.2.deb`

**Windows.** Edge may say the file *isn't commonly downloaded*. Click the three dots by it, then
**Keep**, then **Keep anyway**. Open the file from your Downloads folder. If you see *Windows
protected your PC*, click **More info**, then **Run anyway**. It sets itself up and starts.

:::{admonition} fig-l010-windows-smartscreen
:class: pencil
*Windows protected your PC* after *More info*, with the app's name and the **Run anyway** button.
:::

**macOS.** Open the file. Drag AdvantageScope onto the Applications folder, and start it from
there. If macOS asks, click **Open**.

**Ubuntu.** In Terminal, type `sudo apt install ~/Downloads/advantagescope-linux-x64-v26.0.2.deb`.
Then find AdvantageScope in the app grid and start it.

**Check.**

- AdvantageScope opens on its **Line Graph** tab, with *No data available* on the left.

:::{admonition} fig-l010-advantagescope
:class: pencil
AdvantageScope started for the first time, on its empty Line Graph, with *No data available* in
the sidebar.
:::

::::{only} mentor
**If it didn't**, on Ubuntu, and the first start says *Failed to load assets*, click **Ok**, close
AdvantageScope and start it again.
::::

### L010S040: get the project

The robot's code lives on GitHub. Android Studio copies it to the laptop with a tool called
**git**.

**Clone.**

{.steps}
- On *Welcome to Android Studio*, click **Clone Repository**.

- Into **URL**, type `https://github.com/msb-stitt/ftc31459-26-27-biobuzz`. Leave **Directory** as
  it is.

The first time, Android Studio says *Git is not installed*. How you install git depends on the
laptop.

**Windows.** Click **Download and Install** beside *Git is not installed*. Click **Yes** when
Windows asks. When it says *Git has been installed*, click **Clone**.

:::{admonition} fig-l010-windows-git
:class: pencil
Clone Repository on Windows with the URL typed, *Git is not installed* in red and **Download and
Install** on the right.
:::

**macOS.** macOS asks whether to install the command line developer tools. Click **Install**, then
**Agree**, and wait for it to finish. Quit Android Studio and start it again. Then do the two
**Clone** steps again and click **Clone**.

:::{admonition} fig-l010-macos-tools
:class: pencil
macOS asking *The "git" command requires the command line developer tools*, with **Install**.
:::

**Ubuntu.** Close the box. In Terminal, type `sudo apt install git`. Close Android Studio, start
it again with `/opt/android-studio/bin/studio`, do the two **Clone** steps again and click
**Clone**.

**Trust.** When it asks *Trust and Open Project*, click **Trust Project**. On Windows, a box
about Microsoft Defender is ticked. Leave it ticked.

:::{admonition} fig-l010-windows-trust
:class: pencil
*Trust and Open Project 'ftc31459-26-27-biobuzz'?* on Windows, with the Microsoft Defender box
ticked and **Trust Project** highlighted.
:::

**Check.**

- The project opens, and the Project window lists `FtcRobotController` and `TeamCode`.

::::{only} mentor
**If it didn't**, on macOS, and *Git is not installed* stays after the tools finish, Android
Studio has not looked again. Quit it with ⌘Q, not just its window, and start it again.

On Ubuntu, Android Studio has also closed with *Bus error (core dumped)* while the project first
loaded. Start it again, click **Open**, pick `~/StudioProjects/ftc31459-26-27-biobuzz`, and trust
it again.
::::

### L010S050: answer what Android Studio offers

While the project loads, Android Studio reads it with **Gradle**, the tool that builds the code.
This is called a *sync*. The first sync downloads Java 17 and more, and takes a few minutes.

**Answer.** Notes pop up in the bottom right while it works. Answer each one like this:

- **Agent Mode now available**: click **Do not show again**. The lessons do not use an AI helper.

- **Project update recommended**, *Android Gradle plugin version 8.13.2 has an upgrade available*:
  click **More**, then **Don't ask for this project**. The project needs version 8.13.2, so do not
  upgrade it.

- **Microsoft Defender may affect IDE**, on Windows: click **Exclude folders**.

- Windows may ask if `adb` can use the network. A Mac may ask if Android Studio can find
  devices on the local network. Click **Allow**.

:::{admonition} fig-l010-offers
:class: pencil
The project open after its sync, with *Project update recommended* and *Agent Mode now available*
in the bottom right.
:::

:::{admonition} fig-l010-agp-more
:class: pencil
*Project update recommended* with its **More** menu open: *Remind me tomorrow*, *Don't ask for this
project* and *Don't show again*.
:::

**Check.**

- The Build window's **Sync** tab has a green tick beside the project.

- Open Settings. It is **File → Settings** on Windows and Ubuntu, and **Android Studio →
  Settings** on a Mac. Type `Gradle` in its search box and click **Gradle** under **Build
  Tools**. Under *Gradle JVM criteria*, **Version** reads `17`.

:::{admonition} fig-l010-gradle-jvm
:class: pencil
Settings at Build, Execution, Deployment › Build Tools › Gradle, with *Gradle JVM criteria* and
*Version: 17*.
:::

::::{only} mentor
**If it didn't**, on a Windows laptop with an ARM chip, and the sync fails with
`AccessDeniedException` while moving the downloaded JDK into `.gradle\jdks`, stop the Windows
service `XtaCache` as an administrator and sync again with **File → Sync Project with Gradle
Files**.
::::

### L010S060: build the code

**Build.** Click **Build → Assemble Project**. The first build takes a few minutes.

:::{admonition} fig-l010-build-menu
:class: pencil
The Build menu open, with *Assemble Project* among its items.
:::

**Check.**

- The Build window's **Build Output** tab ends with *BUILD SUCCESSFUL* and *63 actionable tasks:
  63 executed*.

::::{only} mentor
**What you just did.** Android Studio is where the code is written, and Gradle turns the code into
an app for the robot. Clone copied the team's repository from GitHub onto the laptop. The sync read
the project's Gradle files and downloaded what they ask for: Gradle 8.14.3, the Android Gradle
plugin 8.13.2 and Java 17 among them. Assemble Project built `FtcRobotController` and `TeamCode`
into `TeamCode-debug.apk`, the app that is sent to the robot.

**Where next.** [L020](l020.md) copies the first starter into `mytry` and reads the gamepad's
sticks.
::::
