# 153 lesson: measure the volts it takes to move

:::{admonition} fig-l153-fit
:class: pencil
Stand-in for `fig-l153-fit`, made by `book/tools/draw.py`.
:::

The robot drives itself forward, sideways and around, each at four powers. For each way it moves,
it measures two numbers: the volts it takes to start moving, and the volts for each bit of speed
after that. Later lessons use them to ask the motors for a speed and get it.

### L153S030: add up the points, and find the slope

A motor needs some volts before the robot moves at all. That is **kS**, for static: the push it
takes to unstick the wheels. Past that, each inch per second of speed takes more volts. That is
**kV**, for velocity. So:

```
volts = kS + kV × speed
```

That is a straight line. kS is where it crosses zero speed, and kV is how steeply it climbs.

Each run gives one point: the speed the robot settled at, and the volts it took. Real points never
sit exactly on a line. The fit finds the line that misses them the least. It is called a
**least-squares fit**, and it needs only five sums of the points.

**Change.** Open `L153FeedforwardFit`. In `add`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L153FeedforwardFit.java
:emphasize-lines: 4-8

        // When on L153S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s030
        // for what to do here.
        count += 1;
        sumSpeed += speed;
        sumVolts += volts;
        sumSpeedSquared += speed * speed;
        sumSpeedTimesVolts += speed * volts;
```

**Change.** In `kV()`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L153FeedforwardFit.java
:emphasize-lines: 4-6

        // When on L153S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s030
        // for what to do here.
        double top = count * sumSpeedTimesVolts - sumSpeed * sumVolts;
        double bottom = count * sumSpeedSquared - sumSpeed * sumSpeed;
        kV = top / bottom;
```

This is the slope of the least-squares line, as a math book writes it. With two points it is just
the rise over the run: (4 V, 30 in/s) and (2 V, 10 in/s) give 2 V over 20 in/s, a kV of 0.1.

### L153S040: find where the line crosses zero speed

The line goes through the middle of the points. That is the average speed and the average volts.
Walk back from there to zero speed. The volts drop by kV for each unit of speed.

**Change.** In `kS()`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L153FeedforwardFit.java
:emphasize-lines: 4

        // When on L153S040, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s040
        // for what to do here.
        kS = (sumVolts - kV() * sumSpeed) / count;
```

**Check.**

- Run the tests again, as in L153S030. They all pass.

### L153S060: keep each steady run

`measure()` adds up the speed twice in each run. It adds over the third quarter of the run, and
over the last quarter. If the two speeds are the same, the robot had stopped speeding up: the run
was **steady**. Only a steady run gives a point. A run that is still speeding up says nothing about
the speed those volts can hold.

The volts are the power times the battery's volts. `measure()` reads the battery every loop. A
battery at 12 V and one at 13 V push in a different way at the same power. A volt is a volt.

**Change.** In `finishTheRun()`, under the comment that names this step, type:

```{code-block} java
:caption: mytry/L153FeedforwardOpMode.java
:emphasize-lines: 4-17

        // When on L153S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s060
        // for what to do here.
        double earlySpeed = earlySpeedSum / earlyLoops;
        double lateSpeed = lateSpeedSum / lateLoops;
        double volts = lateVoltsSum / lateLoops;
        boolean steady = Math.abs(lateSpeed - earlySpeed) < STEADY_FRACTION * lateSpeed;
        if (steady && axis == Axis.FORWARD) {
            forwardFit.add(volts, lateSpeed);
        } else if (steady && axis == Axis.STRAFE) {
            strafeFit.add(volts, lateSpeed);
        } else if (steady) {
            turnFit.add(volts, lateSpeed);
        }
        Tracker.publish("Run/volts", volts);
        Tracker.publish("Run/speed", lateSpeed);
        Tracker.publish("Run/steady", steady);
```

`STEADY_FRACTION` is 0.03: the two speeds must be within 3% of each other.

**Simulator.** Run the simulator again, as in L153S050. The runs take about a minute.

**Check.**

- When the robot stops for good, the Driver Station says `4 runs` for each.
- In AdvantageScope, the `Fit` folder reads about these. They are the simulator's own numbers:

  | Way | kS | kV |
  | --- | --- | --- |
  | `forward` | 0.60 V | 0.177 V·s/in |
  | `strafe` | 0.96 V | 0.204 V·s/in |
  | `turn` | 0.72 V | 2.82 V·s/rad |

Strafing takes more volts than driving forward for the same speed. The rollers waste some of each
wheel's push, as L132 found.

**What you just did.** The robot measured its own feedforward. The volts a motor needs are not one
number times the speed: some go into getting it moving at all. Volts, not power, are the units,
because the battery's volts change over a match and the robot's need for volts does not. kS and kV
are in the units WPILib's SysId uses, so a number from one can be held against the other. L157 and
L190 use them.
