132 lesson: compare your localizers with the Pinpoint’s¶

Your localizers from L113 and L120 run beside the robot’s own. Yours from L113 reads the drive wheels. Yours from L120 reads the Pinpoint’s pods once a loop. The robot’s own reads the answer the Pinpoint worked out on its own chip. All three are published so they can be graphed against each other. Each loop, your code works out how far each of yours is from the robot’s own, and how fast your localizer from L120 says the robot goes. None of them is the truth. A tape measure is.

Before you start.

  • L113 and L120 are done, so mytry holds L113EncoderLocalizer and L120PinpointLocalizer, and L117 is done, so the Pinpoint is on the robot and tuned.

  • AdvantageScope is installed on the same laptop, and a gamepad is plugged into the laptop.

  • The robot on blocks, as in L050, the Driver Station, a tape measure, and about 3 m of clear floor for the last step.

Check.

  • mytry holds L132CompareLocalizersOpMode, beside your L113EncoderLocalizer and L120PinpointLocalizer.

L132S040: see how often the loop runs¶

Your localizers work out where the robot is once each time loop() runs. The Pinpoint’s chip works it out on its own, about 1500 times a second. Between two of your loops, the robot moves a little, and your localizer takes that move as one step.

AdvantageScope. Leave the simulator running. Open the loop folder and graph period_ms. It is how long the last loop took. It is measured as the OpMode runs.

Check.

  • period_ms is a few milliseconds or more, and it is not the same from one loop to the next.

The Pinpoint’s chip takes about 0.7 ms a step. Write down what period_ms reads in the simulator, to compare with the robot in the next step.

L132S050: work out how far off each localizer is¶

The robot’s own localizer is the one to compare against. Each loop, take each of your localizers’ x, y and heading, and subtract the robot’s own. What is left is the error.

Change. In start(), find the comment that names this step. Under it, type:

mytry/L132CompareLocalizersOpMode.java¶
        // When on L132S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
        // for what to do here.
        Command compareWithPedrosEveryLoop = Commands.infinite(this::compareWithPedros);
        Scheduler.schedule(compareWithPedrosEveryLoop);

The scheduler runs compareWithPedros() before the localizers update. So it compares where each one said the robot was last loop, all at the same moment.

Change. Find the comment for this step just above shadowLocalizers(). Under it, type a new method:

mytry/L132CompareLocalizersOpMode.java¶
    // When on L132S050, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
    // for what to do here.
    /** How far one of your localizers is from the robot's own, in x, y and heading. */
    void publishError(String name, Pose yours, Pose pedros) {
        double xError_in = yours.x() - pedros.x();
        double yError_in = yours.y() - pedros.y();
        double headingError_rad = Angle.normalizeSigned(yours.heading() - pedros.heading());
        Tracker.publish("Error/" + name + "/x_in", xError_in);
        Tracker.publish("Error/" + name + "/y_in", yError_in);
        Tracker.publish("Error/" + name + "/heading_deg", Math.toDegrees(headingError_rad));
    }

A heading of 359° and one of 1° are only 2° apart. Angle.normalizeSigned turns a difference into one between -180° and 180°, so the error is 2°, not 358°.

Change. In compareWithPedros(), under the comment that names this step, type:

mytry/L132CompareLocalizersOpMode.java¶

        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
        // for what to do here.
        Pose pedros = follower.pose();
        publishError("driveWheelEncoders", driveWheelEncoders.pose(), pedros);

Pose and Angle turn red. Click each one and press Option+Enter, as in L113.

Simulator. Run the simulator as in L132S030, and open the Error folder in AdvantageScope.

Your localizer from L113 thinks each wheel pushes at 45°. The wheels in the simulator push more forward than that, as L113 showed, so it says the robot slid farther than it did.

challenge exercise: measure the wheels’ angle¶

This part is a challenge. No later lesson needs it.

Your localizer from L113 counts too much slide, as L132S050 showed. Here you measure how far off it is, then fix it.

Look again at the picture of the four pushes in L113S050. Each wheel pushes the robot at an angle from forward, called α, the Greek letter alpha. Draw the push as an arrow. Its forward part is as long as the arrow times cos α. Its sideways part is as long as the arrow times sin α. At 45°, the two parts are the same length.

When the robot slides, each wheel’s sideways part carries it. A wheel rolls farther than the robot slides: for each inch of slide, the wheel rolls cos α ÷ sin α inches. That number is called cot α, said “cotangent alpha”. At 45° it is 1. At 40° it is about 1.19, so the wheels roll 1.19 in for each inch the robot slides. Your localizer from L113 divides by 1, so it counts 1.19 in of slide.

The fix is to measure cot α. Slide the robot, add up how far the wheels rolled sideways, and add up how far the Pinpoint saw the robot slide. One divided by the other is cot α.

extra challenge exercise: measure the turn radius too¶

This part is harder still. It measures cot α and the turn radius, R, from one run that drives, slides and turns at the same time.

Turning one radian rolls each wheel R inches, as in L131. With A half the robot’s length and B half its width, between the wheel centres, L113 worked out R = A + B. Turning, each wheel’s centre moves forward ω × B and sideways ω × A, where ω is how fast the robot turns. The forward part rolls the wheel ω × B. The sideways part rolls it ω × A × cot α, as sliding does. So:

R = B + A × cot α

At 45°, cot α is 1 and R is A + B, as in L113. The wheels can measure cot α and R, but not A and B on their own. A tape measure gives A and B, to check them.

Each loop, the wheels’ turn mix and slide mix each pick out one part of the motion. The other parts cancel. So one run can measure both.
