# 132 lesson: compare your localizers with the Pinpoint's

Your localizers from L113 and L120 run beside the robot's own. Yours from L113 reads the drive
wheels. Yours from L120 reads the Pinpoint's pods once a loop. The robot's own reads the answer
the Pinpoint worked out on its own chip. All three are published so they can be graphed against
each other. Each loop, your code works out how far each of yours is from the robot's own, and how
fast your localizer from L120 says the robot goes. None of them is the truth. A tape measure is.

**Change.** In `start()`, find the comment that names this step. Under it, type:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-5

        Scheduler.schedule(compareWithPedrosEveryLoop);
```

The scheduler runs `compareWithPedros()` before the localizers update. So it compares where each
one said the robot was last loop, all at the same moment.

**Change.** Find the comment for this step just above `shadowLocalizers()`. Under it, type a new
method:

```{code-block} java
:caption: mytry/L132CompareLocalizersOpMode.java
:emphasize-lines: 4-12

    // When on L132S050, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l132.html#l132s050
    // for what to do here.
    /** How far one of your localizers is from the robot's own, in x, y and heading. */
    void publishError(String name, Pose yours, Pose pedros) {
        double xError_in = yours.x() - pedros.x();
        double yError_in = yours.y() - pedros.y();
        double headingError_rad = Angle.normalizeSigned(yours.heading() - pedros.heading());
        Tracker.publish("Error/" + name + "/x_in", xError_in);
        Tracker.publish("Error/" + name + "/y_in", yError_in);
        Tracker.publish("Error/" + name + "/heading_deg", Math.toDegrees(headingError_rad));
    }
```

A heading of 359° and one of 1° are only 2° apart. `Angle.normalizeSigned` turns a difference into
one between -180° and 180°, so the error is 2°, not 358°.

## challenge exercise: measure the wheels' angle

This part is a challenge. No later lesson needs it.

Your localizer from L113 counts too much slide, as L132S050 showed. Here you measure how far off it
is, then fix it.

Look again at the picture of the four pushes in L113S050. Each wheel pushes the robot at an angle
from forward, called **α**, the Greek letter alpha. Draw the push as an arrow. Its forward part is
as long as the arrow times cos α. Its sideways part is as long as the arrow times sin α. At 45°, the
two parts are the same length.

When the robot slides, each wheel's sideways part carries it. A wheel rolls farther than the robot
slides: for each inch of slide, the wheel rolls cos α ÷ sin α inches. That number is called
**cot α**, said "cotangent alpha". At 45° it is 1. At 40° it is about 1.19, so the wheels roll
1.19 in for each inch the robot slides. Your localizer from L113 divides by 1, so it counts 1.19 in
of slide.

The fix is to measure cot α. Slide the robot, add up how far the wheels rolled sideways, and add up
how far the Pinpoint saw the robot slide. One divided by the other is cot α.

## extra challenge exercise: measure the turn radius too

This part is harder still. It measures cot α and the turn radius, R, from one run that drives,
slides and turns at the same time.

Turning one radian rolls each wheel R inches, as in L131. With A half the robot's length and B
half its width, between the wheel centres, L113 worked out R = A + B. Turning, each wheel's centre
moves forward ω × B and sideways ω × A, where ω is how fast the robot turns. The forward part rolls
the wheel ω × B. The sideways part rolls it ω × A × cot α, as sliding does. So:

R = B + A × cot α

At 45°, cot α is 1 and R is A + B, as in L113. The wheels can measure cot α and R, but not A and B
on their own. A tape measure gives A and B, to check them.

Each loop, the wheels' turn mix and slide mix each pick out one part of the motion. The other
parts cancel. So one run can measure both.
