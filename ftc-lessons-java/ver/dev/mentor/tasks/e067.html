067 what’s happening: drawing a class and its calls¶

When the computer runs your program, it reads one line of code at a time. It moves words and numbers around in its memory. It is like moving sticky notes around on your desk.

In L065 you wrote a class, StickShaper, and an OpMode that uses it. Programmers draw classes in pictures called UML, the Unified Modeling Language. Here are two of them: a class diagram, of what each class has, and a sequence diagram, of who calls whom.

the class diagram¶

A class diagram is a box for each class: its name, then its fields, then its methods. Here is a small class, A, drawn as a box, and its code:

public class A {
    double size;

    public A(double startSize) {
        size = startSize;
    }

    public double grow(double by) {
        size = size + by;
        return size;
    }

    double half() {
        return size / 2;
    }
}

  • double size is a field: its type, then its name.

  • + in front of a name means public: any code can use it. A’s constructor and grow are public.

  • No mark means any class in the same folder can use it. half has no mark.

  • : double after a method is what it gives back.

An arrow with a diamond means has-a: the class at the diamond holds the other one. A field makes it. Here A has-a B:

public class A {
    B b;
}

«enumeration» marks an enum. Its box lists the values it can be. Here A holds (has-a) a Mode, which is ON or OFF:

public class A {
    public enum Mode { ON, OFF }

    Mode mode = Mode.ON;
}

Here are your classes from L065, drawn the same way:

  • StickShaper stickShaper is the OpMode’s field: its type, then its name.

  • You typed public on the constructor, setBand, setShape and shaped, so each has a +. deadband, signedSquared and cubed have no mark.

  • The OpMode has-a StickShaper, and the StickShaper holds (has-a) a Shape.

  • Shape’s box lists LINEAR, SQUARED and CUBED.

The OpMode’s box shows only stickShaper and driveFromTheSticks(). The OpMode has init(), loop() and more, but this diagram is about the shaping. A diagram shows what it is about and leaves out the rest.

the sequence diagram¶

A sequence diagram shows calls in time order, from the top down. Each object has a box and a dashed line down from it. The box says the object’s name, then its class: stickShaper: is the field’s name, and StickShaper is its class. A solid arrow is a call, and a dashed arrow is what the call gives back.

Here an object a calls grow(2) on an object b of class B, and 5 comes back:

        double total = b.grow(2);

An arrow marked new makes the object at its end:

        B b = new B(3);

mytry/l065/L065ShaperOpMode.java¶
    StickShaper stickShaper = new StickShaper(0.05);

  • The first arrow is new. It makes the object, and the constructor keeps 0.05 as its band. This happens once, when the OpMode is made.

mytry/l065/L065ShaperOpMode.java¶
        double leftShapedSpeed = stickShaper.shaped(leftSpeed);
        double rightShapedSpeed = stickShaper.shaped(rightSpeed);

  • shaped(0.5) hands the object the left speed. Its dashed arrow brings back 0.25: past the band, and squared.

  • shaped(-0.5) hands it the right speed, and -0.25 comes back. Each time loop() runs, these two calls happen again.

In L065S080 you added setShape(CUBED) in init(). That is one more arrow, after new and before the first shaped, and then shaped(0.5) gives back 0.125. No arrow from driveFromTheSticks() changes.

The OpMode’s arrows go only to + methods. It never calls deadband or signedSquared, and it never reads band or shape. That is what makes the shape easy to change.
