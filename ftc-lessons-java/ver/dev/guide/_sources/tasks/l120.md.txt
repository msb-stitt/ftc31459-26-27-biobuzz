# 120 lesson: work out where the robot is from the Pinpoint's pods

:::{figure} ../_figures/fig-l120-pods-follow.png
:name: fig-l120-pods-follow
:figclass: file-named

fig-l120-pods-follow.png
:::

The Pinpoint works out where the robot is on its own chip. Here you do the same math yourself,
from the counts of its two pods. Yours runs beside the robot's own, and both are published so they
can be graphed against each other.

::::{only} mentor
**Before you start.**

- L113 is done, and L117 is done, so the Pinpoint is on the robot and the robot's own file in the
  `pedro` folder holds its `localizerConfig`.
- AdvantageScope is installed on the same laptop, and a gamepad is plugged into the laptop.
- The robot, the Driver Station, and about 2 m by 2 m of clear floor for the last step.

In the simulator, a simulated Pinpoint counts the simulated robot's travel, with its pods where
the robot's `localizerConfig` says. It has no slip, so a finished localizer follows the
simulator's own localizer there. The tests check the arithmetic step by step.
::::

## the steps

### L120S020: switch your copy on

**Change.** In `L120PinpointOpMode`, delete the line `@Disabled`, under the comment that names this

**Check.**

### L120S030: run your localizer beside the robot's own

**Change.** In `L120PinpointOpMode`, find `shadowLocalizers()` and the comment that names this
step. Under it, type:

```{code-block} java
:caption: mytry/L120PinpointOpMode.java
:emphasize-lines: 4-7

        // When on L120S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s030
        // for what to do here.
        PinpointSource pinpointSource = HardwarePinpointSource.find(hardwareMap);

        shadowLocalizers.add("pinpointPods", pinpointPods);
```

`find` gives back the robot's Pinpoint, or the simulated one in the simulator. `localizerConfig`
is what L117 measured: where the pods sit, and which way they count.

`PinpointSource`, `HardwarePinpointSource` and `Constants` turn red. Click each one, press
Option+Enter on a Mac or Alt+Enter on Windows, and pick **Import class...**, as in L113S030.

**Simulator.** In the Terminal, run:

```
./gradlew :TeamCode:simRun --args="mytry.L120PinpointOpMode --pad"
```

**AdvantageScope.** Connect to the simulator as in L020. Open the `Localizer` folder, then
`pinpointPods` and `pinPoint` inside it.

**Check.**

- Both start at `x_in` 72, `y_in` 10.5 and `heading_deg` 90.
- Push the left stick forward. `pinPoint/y_in` climbs, and `pinpointPods` stays where it started.

### L120S040: read the pods in inches

Each pod counts **ticks** as it rolls. The Pinpoint's raw count does not know which way a pod was
mounted, or how many ticks make an inch. L117 measured both into `localizerConfig`.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Open `L120PinpointLocalizer`. In
the constructor, find the comment that names this step. Under it, type:

```{code-block} java
:caption: mytry/L120PinpointLocalizer.java
:emphasize-lines: 4-12

        // When on L120S040, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s040
        // for what to do here.
        ticksPerInch = PinpointSource.ticksPerMm(config.podType.get()) * 25.4;
        if (config.xPodDirection.get() == GoBildaPinpointDriver.EncoderDirection.REVERSED) {
            xSign = -1.0;
        }
        if (config.yPodDirection.get() == GoBildaPinpointDriver.EncoderDirection.REVERSED) {
            ySign = -1.0;
        }
        xPodOffset_in = config.xPodOffset.get();
        yPodOffset_in = config.yPodOffset.get();
```

There are 25.4 mm in an inch. A pod set `REVERSED` counts down as the robot moves its way, so its
sign is -1.0.

In `update`, find the next comment that names this step. Under it, type:

```{code-block} java
:caption: mytry/L120PinpointLocalizer.java
:emphasize-lines: 4-21

        // When on L120S040, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s040
        // for what to do here.
        forwardPod_in = xSign * source.getEncoderX() / ticksPerInch;
        strafePod_in = ySign * source.getEncoderY() / ticksPerInch;

        if (firstLoop) {
            firstLoop = false;
            lastForwardPod_in = forwardPod_in;
            lastStrafePod_in = strafePod_in;
            lastRawHeading_rad = rawHeading_rad;
            lastReadTime_s = readTime_s;
            return;
        }

        double forwardPodStep_in = forwardPod_in - lastForwardPod_in;
        double strafePodStep_in = strafePod_in - lastStrafePod_in;
        double turn_rad = rawHeading_rad - lastRawHeading_rad;

        x_in += forwardPodStep_in;
        y_in += strafePodStep_in;
```

This is L113S040 with two pods in place of four wheels. Each pod's step is how far it rolled since
last loop. `turn_rad` is how far the robot turned. `readTime_s` is when the Pinpoint was read, in
seconds, and L120S070 uses it.

**Check.**

- In the Terminal, run this. It prints `9 tests completed, 5 failed`. The five that fail pass by
  the end of L120S070.

  ```
  ./gradlew :TeamCode:testDebugUnitTest --tests '*L120PinpointLocalizerTest*'
  ```

`turningOnTheSpotDoesNotMoveIt` is one that fails. That is the next step.

### L120S050: take out what turning rolled

:::{figure} ../_figures/fig-l120-pod-turn.png
:name: fig-l120-pod-turn
:figclass: file-named

fig-l120-pod-turn.png
:::

The pods do not sit at the robot's middle. When the robot turns on the spot, each pod rolls along a
circle around the middle, and counts it. The forward pod sits `xPodOffset_in` to the left of the
middle. Turning left rolls it backward by that offset times the turn. The strafe pod sits
`yPodOffset_in` ahead of the middle, and the same turn rolls it to the left.

The four drive wheels in L113 sit in pairs on each side, so a turn rolled them by equal and
opposite amounts that cancelled. The pods do not cancel, so you take the turn out.

**Change.** Delete the two lines `x_in += forwardPodStep_in;` and `y_in += strafePodStep_in;`. Find
the comment that names this step. Under it, type:

```{code-block} java
:caption: mytry/L120PinpointLocalizer.java
:emphasize-lines: 4-8

        // When on L120S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s050
        // for what to do here.
        double forward_in = forwardPodStep_in + xPodOffset_in * turn_rad;
        double strafe_in = strafePodStep_in - yPodOffset_in * turn_rad;

        x_in += forward_in;
        y_in += strafe_in;
```

**Check.**

- Run the same test command again. It prints `9 tests completed, 4 failed`.

Two that fail are `appliesTheHeadingSoForwardIsTheRobots` and
`setPoseMovesTheEstimateWithoutMovingTheRobot`, as in L113S040. Both are about which way the robot
faces.

### L120S060: turn the step to face the way the robot faces

**Change.** Delete the two lines `x_in += forward_in;` and `y_in += strafe_in;`. Find the comment
that names this step. Under it, type the same lines as in L113S050:

```{code-block} java
:caption: mytry/L120PinpointLocalizer.java
:emphasize-lines: 4-8

        // When on L120S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s060
        // for what to do here.
        double heading_rad = rawHeading_rad + headingOffset_rad;
        double sinHeading = Math.sin(heading_rad);
        double cosHeading = Math.cos(heading_rad);
        x_in += forward_in * cosHeading - strafe_in * sinHeading;
        y_in += forward_in * sinHeading + strafe_in * cosHeading;
```

**Check.**

- Run the same test command again. It prints `9 tests completed, 2 failed`. Both are about speed.

**Simulator.** Run the command from L120S030 again, and connect AdvantageScope.

**Check.**

- Drive around the field, turning as you go. `pinpointPods` follows `pinPoint`: `x_in`, `y_in`
  and `heading_deg` each stay within half an inch or half a degree.

### L120S070: work out how fast the robot is going

Speed is how far, divided by how long. `forward_in`, `strafe_in` and `turn_rad` are how far the
robot went this loop. The time is how long since the Pinpoint was last read.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Find the comment that names this
step. Under it, type:

```{code-block} java
:caption: mytry/L120PinpointLocalizer.java
:emphasize-lines: 4-7

        // When on L120S070, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l120.html#l120s070
        // for what to do here.
        double period_s = readTime_s - lastReadTime_s;
        forwardSpeed_ips = forward_in / period_s;
        strafeSpeed_ips = strafe_in / period_s;
        turnSpeed_radps = turn_rad / period_s;
```

`_ips` is inches per second, and `_radps` is radians per second. A loop is not always the same
length, so each loop divides by its own time.

These speeds are the robot's own: forward is the way its nose points, not up the field. That is
how Pedro wants them. `state()` hands them to Pedro.

**Check.**

- Run the same test command again. It ends with `BUILD SUCCESSFUL`.

### L120S080: drive it on the robot

**Robot.** Stop the simulator. Send the code, run `L120 Pinpoint` from the Driver Station, and
watch it in AdvantageScope.

**Check.**

- Drive around and stop. `pinpointPods` and `pinPoint` read the same two pods, so they stay close.

::::{only} mentor
**Our tests.** `LessonsTest.l120_thePinpointLocalizerFollowsTheRobot` drives the simulated robot
forward, left and turning for 100 loops, and checks yours against the simulator's own localizer.

**If it didn't**, and the robot's estimate drifts sideways as it turns, a sign in L120S050 is
wrong. With the `+` in the `forward_in` line made a `-`, `turningOnTheSpotDoesNotMoveIt` fails with
`both pods rolled, but only from turning: y expected:<0.0> but was:<-6.284174784625778>`.

**If it didn't**, and `dividesByEachLoopsOwnTime` fails in L120S070, a speed is divided by the
wrong time. With `forward_in / readTime_s` in place of `forward_in / period_s`, it fails with
`expected:<60.0> but was:<39.97491123861896>`.

**The speed is not graphed.** Only `x_in`, `y_in` and `heading_deg` are published for a shadow.
L132 logs it against Pedro's.

**If it didn't**, and `pinpointPods` goes backward while the robot goes forward on the robot but not
in the simulator, the Pinpoint's raw count may already apply the `REVERSED` setting. The simulator
takes it that it does not.

**What you just did.** The Pinpoint's chip does this same math, and more often than your loop
runs. L132 graphs your two localizers and the Pinpoint's against each other.
