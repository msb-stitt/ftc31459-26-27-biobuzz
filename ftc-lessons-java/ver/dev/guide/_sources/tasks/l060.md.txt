### L060S030: write a deadband

A stick that has been let go does not always read 0.0. It can read a few hundredths, and a few
hundredths of full speed is enough to make a robot crawl across the floor on its own. A **deadband**
fixes that: any reading closer to the middle than the band counts as let go.

**Change.** Scroll to the bottom of the file and find the comment that names this step. Under it,
write a method of your own:

```{code-block} java
:caption: mytry/L060ShapingOpMode.java
:emphasize-lines: 4-11

    // When on L060S030, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l060.html#l060s030
    // for what to do here.
    double deadband(double value, double band) {
        double alwaysPositiveMagnitude = Math.abs(value);
        boolean isCloseToZero = alwaysPositiveMagnitude < band;
        if (isCloseToZero) {
            return 0.0;
        }
        return value;
    }
```

A **method** is a named piece of code you can use again. This one takes two numbers, `value` and
`band`, and gives back one number. `value` and `band` are its **parameters**: the names the two
numbers have inside the method. `return` is the number it gives back.

Each line does one thing, and each result gets a name:

- `Math.abs` takes the minus sign off: `Math.abs(-0.03)` is 0.03. `alwaysPositiveMagnitude` is
  the size of the reading without its sign. A stick pulled halfway back gives -0.5, and -0.5 is
  less than 0.05. But it is far from the middle, so it has to be compared without its minus sign.
- `<` compares two numbers, and its answer is true or false. A **`boolean`** holds true or false,
  the way a `double` holds a number. `isCloseToZero` is true when the size is inside the band.
- `if` runs the lines inside its `{ }` only when what is in its brackets is true. Here,
  `return 0.0` runs only for a stick close to the middle.

**Check.**

- The method has no red underline.
- `deadband` is gray, with *no usages* above it. Nothing uses it yet.

### L060S050: write squaring

With the deadband in, a tenth of a push is still a tenth of full speed. Near the middle that is more
robot than a driver wants. **Squaring** fixes it: half a push becomes a quarter of full speed, and
a full push is still full speed.

**Change.** Press Ctrl+C in the Terminal to stop the simulator. Find the comment that names this
step. Under it, write a second method:

```{code-block} java
:caption: mytry/L060ShapingOpMode.java
:emphasize-lines: 4-8

    // When on L060S050, see
    // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l060.html#l060s050
    // for what to do here.
    double signedSquared(double value) {
        double alwaysPositiveValue = Math.abs(value);
        double valueSquaredKeepingTheSign = value * alwaysPositiveValue;
        return valueSquaredKeepingTheSign;
    }
```

Squaring a number makes it positive. A plus times a plus is a plus. A minus times a minus is a plus
too:

- `+0.5 * +0.5` is `+0.25`
- `-0.5 * -0.5` is `+0.25`

Backward would turn into forward. To keep the speed's sign, the method multiplies by the size of
the number instead:

- `+0.5 * Math.abs(+0.5)` is `+0.5 * +0.5`, which is `+0.25`
- `-0.5 * Math.abs(-0.5)` is `-0.5 * +0.5`, which is `-0.25`, since a negative times a positive is
  negative

So it squares the size of the number, its magnitude, and keeps its sign. That is why it is called
`signedSquared`. `alwaysPositiveValue` holds the size, `valueSquaredKeepingTheSign` names the
answer, and `return` gives it back.

**Check.**

- The method has no red underline.

### L060S060: use squaring

**Change.** Go back to the two `deadband` lines from L060S040. Under each one, add a line that
squares the shaped speed:

```{code-block} java
:caption: mytry/L060ShapingOpMode.java
:emphasize-lines: 2

        double leftShapedSpeed = deadband(leftSpeed, bandToSetToZero);
        leftShapedSpeed = signedSquared(leftShapedSpeed);
```

```{code-block} java
:caption: mytry/L060ShapingOpMode.java
:emphasize-lines: 2

        double rightShapedSpeed = deadband(rightSpeed, bandToSetToZero);
        rightShapedSpeed = signedSquared(rightShapedSpeed);
```

`signedSquared` works on what `deadband` gave back, and puts its answer back in the same name. The
line has no `double` in front: `leftShapedSpeed` already exists, so the line changes it rather than
making a new one.

**Simulator.** Run the same command again, and connect AdvantageScope.

**Check.**

- Push the left stick halfway forward. `drivetrain/leftSpeed` reads 0.5, and
  `drivetrain/leftShapedSpeed` reads 0.25.
- Push it all the way, and both read 1.0.
- Pull it back, and the shaped speed goes below 0.0.

**AdvantageScope.**

{.steps}

- Open **File > Connect to Robot > NetworkTables 4**. AdvantageScope still has the robot's address
  from L050.

**Check.**

- The title bar reads `192.168.43.1`.

**Run.** Press PLAY. Drag `leftSpeed` and `leftShapedSpeed` from the `drivetrain` folder into
**Left Axis**.

**Check.**

- Let go of both sticks, and the robot sits still, with `drivetrain/leftShapedSpeed` at 0.0.
- Push a stick about a third of the way, and the robot creeps along under control.
- Push it all the way, and the robot goes full speed.

::::{only} mentor
**No gamepad.** `--args="mytry.L060ShapingOpMode --left_stick_y=-0.03 --right_stick_y=0.04"` holds
both sticks just off center; the first picture was taken that way. `--left_stick_y=-0.5
--right_stick_y=0.5` holds them half forward and half back for the second.

**If it didn't**, and the robot still creeps on the floor, the band is smaller than what this
gamepad reads when it is let go. Raise it a little: 0.05 to 0.1 is the usual range. A band much
bigger than that throws away real driving.

**If it didn't**, and the robot goes forward but will not back up, a sign was lost. Check
`signedSquared` uses `Math.abs`, and `deadband` too.

**What you just did.** Both methods sit between the speed and the wheels. Each one takes a number
and gives one back, and neither knows what a wheel is. `drivetrain/leftSpeed` is still what the
stick asks for, and `drivetrain/leftShapedSpeed` is what the wheels get, so AdvantageScope shows
both side by side.
