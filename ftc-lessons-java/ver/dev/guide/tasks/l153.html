153 lesson: measure the volts it takes to move¶

The robot drives itself forward, sideways and around, each at four powers. For each way it moves, it measures two numbers: the volts it takes to start moving, and the volts for each bit of speed after that. Later lessons use them to ask the motors for a speed and get it.

the steps¶

L153S010: copy the two starters into mytry¶

This lesson has two files. L153FeedforwardOpMode is the auto that drives the runs. L153FeedforwardFit turns what the runs found into the two numbers.

Copy. In lessons, click L153FeedforwardFit once. Hold Shift and click L153FeedforwardOpMode, so both are picked. Copy them, click mytry once, and paste. In the Copy box, click OK. If Android Studio asks whether to add the files to Git, click Add.

Copy both at once. Copied one at a time, the OpMode still points at the fit in lessons, and turns red.

Check.

  • mytry holds L153FeedforwardFit and L153FeedforwardOpMode, and neither shows red.

L153S020: switch your copy on¶

Change. In L153FeedforwardOpMode, delete the line @Disabled, under the comment that names this step.

Check.

  • Under the step’s comment, the next line reads // 'public' so the robot can run this OpMode. 'public' allows access from any code.

L153S030: add up the points, and find the slope¶

A motor needs some volts before the robot moves at all. That is kS, for static: the push it takes to unstick the wheels. Past that, each inch per second of speed takes more volts. That is kV, for velocity. So:

volts = kS + kV × speed

That is a straight line. kS is where it crosses zero speed, and kV is how steeply it climbs.

Each run gives one point: the speed the robot settled at, and the volts it took. Real points never sit exactly on a line. The fit finds the line that misses them the least. It is called a least-squares fit, and it needs only five sums of the points.

Change. Open L153FeedforwardFit. In add, under the comment that names this step, type:

mytry/L153FeedforwardFit.java¶
        // When on L153S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s030
        // for what to do here.
        count += 1;
        sumSpeed += speed;
        sumVolts += volts;
        sumSpeedSquared += speed * speed;
        sumSpeedTimesVolts += speed * volts;

Change. In kV(), under the comment that names this step, type:

mytry/L153FeedforwardFit.java¶
        // When on L153S030, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s030
        // for what to do here.
        double top = count * sumSpeedTimesVolts - sumSpeed * sumVolts;
        double bottom = count * sumSpeedSquared - sumSpeed * sumSpeed;
        kV = top / bottom;

This is the slope of the least-squares line, as a math book writes it. With two points it is just the rise over the run: (4 V, 30 in/s) and (2 V, 10 in/s) give 2 V over 20 in/s, a kV of 0.1.

Check.

  • In the Terminal, run this. It prints 4 tests completed, 4 failed. Each one fails on kS, which is L153S040.

    ./gradlew :TeamCode:testDebugUnitTest --tests '*L153FeedforwardFitTest*'

L153S040: find where the line crosses zero speed¶

The line goes through the middle of the points. That is the average speed and the average volts. Walk back from there to zero speed. The volts drop by kV for each unit of speed.

Change. In kS(), under the comment that names this step, type:

mytry/L153FeedforwardFit.java¶
        // When on L153S040, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s040
        // for what to do here.
        kS = (sumVolts - kV() * sumSpeed) / count;

Check.

  • Run the tests again, as in L153S030. They all pass.

L153S050: line up the runs¶

Open L153FeedforwardOpMode. oneRun is one run: drive one way at one power with follower.manual, stop in time, hold still, and keep what it found.

A forward run must stop inside 72 in, braking included. So the run stops early, by how far the robot slid to a stop last time at that speed.

Change. In theRuns(), under the comment that names this step, type:

mytry/L153FeedforwardOpMode.java¶
        // When on L153S050, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s050
        // for what to do here.
        Command turnRuns = sequential(
                oneRun(Axis.TURN, 0.2), oneRun(Axis.TURN, 0.4),
                oneRun(Axis.TURN, 0.6), oneRun(Axis.TURN, 0.8));
        Command forwardRuns = sequential(
                oneRun(Axis.FORWARD, 0.2), oneRun(Axis.FORWARD, -0.4),
                oneRun(Axis.FORWARD, 0.6), oneRun(Axis.FORWARD, -0.8));
        Command strafeRuns = sequential(
                oneRun(Axis.STRAFE, 0.2), oneRun(Axis.STRAFE, -0.4),
                oneRun(Axis.STRAFE, 0.6), oneRun(Axis.STRAFE, -0.8));
        Command runs = sequential(turnRuns, forwardRuns, strafeRuns, instant(this::publishTheFits));
        return runs;

Then delete return Command.NOOP; under it.

The minus signs send every other run back the way it came, so the robot needs only 72 in of floor each way.

Simulator. In the Terminal, run:

./gradlew :TeamCode:simRun --args="mytry.L153FeedforwardOpMode"

AdvantageScope. Connect to the simulator as in L020, and click 2D Field.

Check.

  • The robot turns on the spot four times, each a whole turn and faster than the last.

  • Then it drives forward and back four times, then left and right four times.

  • The Driver Station says 0 runs for each, because nothing keeps a run yet. That is L153S060.

L153S060: keep each steady run¶

measure() adds up the speed twice in each run. It adds over the third quarter of the run, and over the last quarter. If the two speeds are the same, the robot had stopped speeding up: the run was steady. Only a steady run gives a point. A run that is still speeding up says nothing about the speed those volts can hold.

The volts are the power times the battery’s volts. measure() reads the battery every loop. A battery at 12 V and one at 13 V push in a different way at the same power. A volt is a volt.

Change. In finishTheRun(), under the comment that names this step, type:

mytry/L153FeedforwardOpMode.java¶
        // When on L153S060, see
        // https://coding.stitt.cc/ftc-lessons-java/guide/tasks/l153.html#l153s060
        // for what to do here.
        double earlySpeed = earlySpeedSum / earlyLoops;
        double lateSpeed = lateSpeedSum / lateLoops;
        double volts = lateVoltsSum / lateLoops;
        boolean steady = Math.abs(lateSpeed - earlySpeed) < STEADY_FRACTION * lateSpeed;
        if (steady && axis == Axis.FORWARD) {
            forwardFit.add(volts, lateSpeed);
        } else if (steady && axis == Axis.STRAFE) {
            strafeFit.add(volts, lateSpeed);
        } else if (steady) {
            turnFit.add(volts, lateSpeed);
        }
        Tracker.publish("Run/volts", volts);
        Tracker.publish("Run/speed", lateSpeed);
        Tracker.publish("Run/steady", steady);

STEADY_FRACTION is 0.03: the two speeds must be within 3% of each other.

Simulator. Run the simulator again, as in L153S050. The runs take about a minute.

Check.

  • When the robot stops for good, the Driver Station says 4 runs for each.

  • In AdvantageScope, the Fit folder reads about these. They are the simulator’s own numbers:

    Way

    kS

    kV

    forward

    0.60 V

    0.177 V·s/in

    strafe

    0.96 V

    0.204 V·s/in

    turn

    0.72 V

    2.82 V·s/rad

Strafing takes more volts than driving forward for the same speed. The rollers waste some of each wheel’s push, as L132 found.

L153S070: measure your robot¶

Robot. Stop the simulator. Put the robot on the floor with 2 m clear ahead of it and 2 m clear to its left. Send the code, and run L153 Feedforward from the Driver Station.

Check.

  • The robot turns four times, drives forward and back four times, and slides left and right four times, and stays on the clear floor.

  • The Driver Station shows a kS and a kV for each way, with 4 runs or 3 runs.

A run that never steadied is left out. A heavy robot may not reach a steady speed at 0.8 power in 72 in. Three runs still make a line.

Change. Open the file of the robot thisRobot names, in the pedro folder, such as Bot37523. Put the six numbers in kSForwardVolts, kVForwardVoltSecondsPerInch, kSStrafeVolts, kVStrafeVoltSecondsPerInch, kSTurnVolts and kVTurnVoltSecondsPerRadian, in place of the simulator’s.

Run it twice more. Three answers close together are a measurement.
